# phase 3.5

[Phase 3.5] : 리팩토링 후 성능 검증 및 교차모델 재시도

1. 개요 및 연구 배경
Phase 3.5에서는 이전 단계에서 관찰된 비정상적으로 높은 모델 성능의 원인을 철저히 규명하고자 데이터 누수를 완전히 제거한 상태에서의 베이스라인 성능 재평가를 수행하였다. 연구팀은 코드 리팩토링을 통해 데이터 정합성 검증 절차를 강화하고, 여러 알고리즘에 대한 동일 조건 비교 실험을 실시하여 실제 신호만으로 얻을 수 있는 예측 한계를 확인하고자 했다. 또한 누수 제거 후 저조해진 성능을 개선하기 위한 방안으로, 라그(Lag) 피처 추가, 현재 패스 관련 피처 제거, Plate별 정규화 적용 등 다양한 전처리 아이디어를 교차 검증하였다. 아울러, 과거에 잠시 시도되었던 Entry-Exit 교차모델 학습을 깨끗해진 데이터에 다시 도입하여 성능 향상 가능성을 탐색하였다.

2. 기술적 구현 및 감사 결과
 누수 차단 및 자동 검증 장치: 리팩토링된 코드에서는 _hard_leak_guard 함수를 도입하여 피처 컬럼명에 "target", "label" 등이 포함된 경우 학습 입력에서 자동 제외하도록 구현되었다. 이를 통해 이전 Phase에서 확인된 Pattern A (Label Leak) 유형의 레이블 누수를 원천 차단하였다. 아울러 LEAK_AUTOCHECK=1 설정을 통해 퍼뮤테이션 검증이 매 실험마다 자동 수행되도록 하였는데, 실제 로그상 무작위 타깃Permutation을 적용한 모델의 R² 값이 -0.5 내외의 큰 음수로 출력되어, 리팩토링 후 파이프라인에는 더 이상 명백한 누수가 없음을 확인하였다.
 모델 훈련 구조 모듈화: 코드 리팩토링을 통해 데이터 전처리부터 모델 훈련까지의 파이프라인이 하나의 템플릿으로 통합되고, 회귀 알고리즘만 바꾸어 끼울 수 있는 모듈화 구조로 개선되었다. 이에 따라 RandomForest, XGBoost, ExtraTrees 등 여러 모델을 동일한 데이터셋과 설정에서 반복 실행하는 것이 가능해졌다. 실제 035~041번 실험에서 이러한 구조를 활용하여 각기 다른 알고리즘을 교체 적용한 결과, 모든 모델의 평균 Test R²가 0.1096으로 동일하게 나타났다. 이는 코드 상에서 난수 시드 고정과 동일한 전처리 절차가 일관되게 적용되었음을 시사하며, 어떤 알고리즘을 쓰더라도 현재 피처 구성에서 얻을 수 있는 예측 성능 한계치가 약 0.11 수준임을 명확히 보여준다. 또한 각 모델 실험에서 수행된 퍼뮤테이션 검증 결과 역시 일관되게 -0.5058 수준으로 나타나, 데이터 내에 학습 가능한 실제 신호량의 한계를 재확인하였다.
 피처 토글 그리드 실험 구현: 026번 스크립트에서는 하나의 코드에서 여러 전처리 조합을 순차 실행하는 그리드 실험 구조가 도입되었다. 예를 들어, 기본 설정(S0) 대비 특정 옵션을 켠 실험(S0+R1: 현재 패스 피처 제거, S0+L1: Lag 피처 추가, S0+PN1: Plate Normalization 적용 등)을 반복문으로 자동 수행하고, 결과를 요약 출력하도록 하였다. 이러한 구현으로 단일 실행으로도 여러 설정에 대한 성능 변화를 비교할 수 있었는데, 감사 결과 요약 파일명에 각 설정 조합과 성능이 함께 기록되는 방식으로 체계화되었다. 이 그리드 실험의 결과, Lag 피처를 추가한 경우 Test R²가 -1.3055까지 급락하고, Plate 단위 정규화를 적용한 경우 -0.5775로 성능이 악화되는 등 누수 제거 후 일부 피처 엔지니어링 기법들이 오히려 데이터 불일치를 야기함을 확인하였다. 한편 현재 패스 관련 지표를 제거한 설정(S0+R1)은 R²가 0.0960에서 0.0926으로 미미하게 감소하여, 해당 피처의 영향력이 크지 않음을 보여주었다.
 Entry-Exit 교차모델 학습 루틴 추가: 032번 실험부터 두 개의 모델을 교대로 학습시키는 새로운 루프 구조가 코드에 도입되었다. 한 epoch 내에서 Entry 모델의 예측을 Exit 모델 입력에 활용하고, 다시 Exit 예측치를 Entry 모델 학습에 반영하는 형태로, Entry와 Exit 방향 예측기를 번갈아 훈련시키는 로직이다. 코드 플래그 예를 들면 ANCHOR_FROM_CROSS가 활성화되면 한 모델의 예측값을 다른 모델의 입력 피처로 고정(앵커)하는 기능을 수행하도록 구현되었다. 감사 결과, 이 교차모델 구현은 설정에 극도로 민감하여 작은 변경에도 성능이 크게 요동치는 것으로 나타났다. 실제 045번 스크립트에서는 앵커 활용 관련 설정 버그로 추정되는 문제가 있어 평균 Test R²가 -0.0083에 불과했으나, 동일 코드에서 조건을 수정한 046번 실험에서는 R²가 0.2043으로 정상 회복되었다. 이는 045→046 코드 diff에서 인덱스 정렬이나 피처 투입 조건이 수정되었을 가능성을 시사하며, 교차모델의 세부 구현 오류가 성능 실패의 원인이었음을 뒷받침한다.
 잔존 누수 패턴 점검: 엄격한 감사 결과, 리팩토링 후 코드에서도 몇 가지 잔존 위험 요인이 식별되었다. 우선, 전처리 과정에서 전체 데이터를 대상으로 산출된 통계치와 변환을 사용하는 관행이 남아 있었다. 예를 들어 RM 데이터의 글로벌 통계량 결합 및 정규화(스케일링)가 train/test 분리 이전에 수행되어, 훈련 피처에 테스트셋 정보가 반영되는 Pattern C (Transductive Leak) 가능성이 확인되었다. 이는 Phase 4에서 해당 스케일링 누수를 제거하는 개선 조치로 이어진 부분이다. 또한, 일부 시계열 특성 생성 로직에서 미래 값 참조 위험이 발견되었다. df.groupby(...).shift(-1) 연산을 통한 피처 생성이 그 예로, 동일 Plate 내 연속 패스의 지표를 이동 평균할 때 자칫 다음 패스의 값을 현재 패스의 피처에 포함시키는 오류로 연결될 수 있다. 이러한 Pattern B (Sequence Leak) 유형의 결함은 Phase 3.5 코드에서도 잠재적으로 존재하여, 엄밀한 구현 검증이 필요한 영역으로 지적되었다. 다행히 Label 자체가 피처에 포함되는 치명적 누수는 Leak Guard로 차단되었고, permutation 테스트 결과도 양호하여 이상치 탐지나 시퀀스 처리상의 누수가 모델 성능에 직접적인 영향을 주지는 않은 것으로 분석된다. 그러나 연구팀은 이와 같은 숨어 있는 데이터 처리상의 맹점을 인지하고, 차후 Phase에서 Train 전용 통계 적용* 등 추가적인 누수 차단 조치를 실행하게 되었다.

3. 실험 결과 및 시사점
 베이스라인 성능 재설정: 데이터 누수를 제거한 후 재실행된 026번 실험에서 평균 Test R²가 약 0.096으로 급격히 하락하였다. 이전 Phase까지 약 0.90에 달했던 비현실적 성능이 거의 0에 수렴한 것으로, 이는 기존 고득점이 모델의 일반화 능력에 의한 것이 아니라 데이터 누수에 기인한 허수였음을 입증한다. 누수를 차단하자 Train과 Test 성능 격차도 크게 벌어졌으며, 테스트셋에서의 예측력이 사실상 사라지는 것을 확인하였다. 이로써 연구팀은 모델의 진짜 베이스라인을 0에 가까운 R² 수준에서 재정의하고, 향후에는 편법이 아닌 실제 예측 신호를 찾아 성능을 높이는 방향으로 전략을 전환하였다.
 다양한 알고리즘 비교 실험: 리팩토링된 파이프라인의 일관성 하에 XGBoost, RandomForest, ExtraTrees, HistGradientBoosting 등 다양한 모델을 동일 조건으로 학습시킨 결과, 모든 알고리즘의 Test R²가 약 0.11 수준으로 수렴하였다. 이는 데이터셋의 정보량이 제한적이어서 어떤 모델을 쓰더라도 얻을 수 있는 최대 성능이 그 수준임을 의미한다. 또한 각 모델별 타깃 셔플(permutation) 테스트에서 R²가 일관되게 약 -0.50으로 관측되었는데, 이는 모델이 더 이상 정답지를 학습하는 누수 효과 없이 무작위 수준 이하의 출력을 내고 있음을 보여준다. 이러한 결과는 누수 제거 후 현재의 피처 구성만으로는 예측 난이도가 높아, 고도화된 모델보다는 추가적인 데이터/피처 개선이 필요함을 시사한다.
 피처 엔지니어링 토글의 영향: 누수 없는 환경에서 여러 피처 전략을 시험한 결과, 대부분 유의미한 성능 향상을 이루지 못했다. Lag 피처 도입의 경우 오히려 모델이 혼란을 일으켜 Test R²가 -1.3055로 급락하였고, Plate 단위 정규화 적용 시에도 R²가 -0.5775로 악화되었다. 반면, 현재 패스 관련 지표 제거는 성능을 0.0960에서 0.0926 수준으로 소폭 감소시키는 데 그쳐, 해당 피처가 기존 모델에 큰 기여를 하지 않았음을 보여주었다. 요약하면, 데이터 누수가 제거된 상태에서는 이들 추가 피처 또는 전처리 기법들이 예상과 달리 성과를 내지 못하거나 오히려 역효과를 낳았다. 이는 일부 기법이 훈련/테스트 분포 불일치를 키웠거나, 기존 누수 상황에서만 유효했던 트릭이었음을 의미한다. 연구팀은 이 결과를 통해 피처 엔지니어링보다는 데이터 처리 오류 개선에 더욱 무게를 두기로 하였다.
 교차모델 재시도의 성과와 한계: Entry-Exit 교차모델을 다시 적용한 초기 실험(032번)에서는 평균 Test R²가 0.2937로 일시적으로 크게 상승하였다. 이는 Entry 전용 모델과 Exit 전용 모델을 별개로 돌렸을 때(≈0.10)에 비해 상당한 향상으로, 두 방향 정보를 상호 보완하면 성능을 끌어올릴 여지가 있음을 보여준 사례였다. 그러나 후속 실험들에서 이 성능은 재현성과 안정성이 부족한 것으로 드러났다. 동일한 교차 학습 전략을 반복한 042, 044, 046, 049번 실험들은 Test R²가 0.20 안팎으로 다소 향상된 수준에 머문 반면, 약간의 설정 변경이 있었던 045번과 050~051번 실험에서는 R²가 0에 수렴하거나 음수로 나타나는 실패 사례가 발생했다. 이는 교차모델 접근법이 아이디어 차원에서는 유효해 보이지만, 구현 세부 조건에 매우 민감한 불안정한 방법임을 의미한다. 특히 앵커 피처 사용 여부나 학습 스케줄 조정 같은 작은 요소 차이가 성패를 갈랐으며, 교차모델 코드에 아직 잠복한 버그 가능성도 배제할 수 없다. 이러한 한계로 인해 연구팀은 교차모델의 잠재력은 인지하되, 우선순위를 데이터 처리 오류 교정에 두고 향후 해당 기법을 재정비하기로 하였다.
 검증 완료 및 다음 단계로의 함의: Phase 3.5를 통해 모델의 실제 실력과 데이터 누수의 영향이 분명하게 구분되었다. 누수 차단 후 모델 성능이 현실적인 수준(0.1 미만)으로 떨어짐으로써 문제의 근본 원인이 제거되었고, 이제는 이 낮은 성능을 끌어올리기 위한 올바른 노력이 가능해졌다. 동시에 교차모델 등으로 약간의 개선 여지를 보았지만, 평균 0.2 수준의 R² 벽을 넘지 못한 채 정체되었다. 이에 연구팀은 데이터 자체에 남은 문제를 다시 한번 의심하게 되었으며, 특히 데이터 정규화 및 분포 차에 주목하게 되었다. Phase 3.5 말미에 제기된 “아직 어딘가 새는 부분이 있는지”에 대한 의문과 “정규화 범위를 다시 점검하자”는 논의는, 결국 다음 Phase에서 Train/Test 스케일링 누수를 발견하고 교정하는 결정적인 단초가 되었다. 결과적으로 Phase 3.5는 누수를 철저히 감시하고 초기화를 완료한 전환점으로서, 이후 본격적인 성능 향상을 위한 기초 체력 다지기 단계*를 마무리한 셈이다.
