# phase 8

[Phase 8] : 롤포워드 검증 도입과 하이퍼파라미터 튜닝 결과 분석

1. 개요 및 연구 배경
Phase 7에서 모델링 방향을 정립한 연구팀은 실제 배포 환경과 유사한 엄격한 검증 체계를 도입하고자 하였습니다. 이에 시간 순서 기반 롤포워드 검증 기법을 Phase 8부터 적용하였습니다. 기존에는 압연 판(Plate) 단위로 데이터를 무작위 분할하여 검증했으나, 이번 단계에서는 각 판의 초기 구간 데이터를 학습에 사용하고 이후 구간을 검증에 사용하도록 변경하였습니다. 이러한 순차적 데이터 분할은 미래 정보가 학습 단계에 섞여 들어가는 가능성을 원천 차단하여 모델의 실제 예측 성능을 엄밀히 평가하려는 목적이었습니다. 이 새로운 평가 프로토콜 도입으로 모델의 평균 Test R²가 이전 Phase의 0.90대에서 약 0.05 수준으로 급락하였습니다. 이는 종전의 높은 성능 지표가 데이터 누수 등의 영향으로 과대평가되었음을 의미하며, 모델의 실제 예측 난이도를 드러낸 결과입니다. 이러한 환경에서 연구팀은 남은 성능 향상 수단으로 하이퍼파라미터 튜닝(Grid Search)을 선택하였습니다. 모델 구조와 피처 엔지니어링의 큰 틀은 Phase 7까지 완료되었기에, Phase 8에서는 학습률, 트리 깊이, 피처 선택 개수 등의 세부 설정을 체계적으로 탐색하여 최적 조합을 모색하는데 주력하였습니다.

2. 기술적 구현 및 감사 결과
- 롤포워드 검증 구현: scripts/119_test.py 코드를 확인한 결과, 데이터 분할 로직이 시간 축을 따르도록 개편되었습니다. 예를 들어, 기존 GroupShuffleSplit 기반의 무작위 분리 코드가 119 실험부터는 train_idx = df[df['판번호'] <= cutoff].index 등의 방식으로 일정 시점(cutoff) 이전의 데이터만 학습에 사용하고 이후 시점 데이터를 테스트로 사용하는 로직으로 대체되었습니다. Plate 내 과거 패스(pass) 데이터만 훈련세트에 포함하고 이후 미래 패스를 검증하는 이 전략을 통해, 데이터 누수 없는 순차 예측 평가가 구현되었습니다. 또한 모델 입력 구성 시 _hard_leak_guard 함수와 EXCLUDE_FROM_X 설정이 도입되어, 타깃 값(_target 컬럼)이나 판번호 등의 식별자가 피처로 사용되는 것을 원천 차단하였습니다. 실제로 119_test 코드에서는 TARGET_COL, PLATE_COL 등을 EXCLUDE_FROM_X 집합에 명시한 뒤 학습 피처에서 제거하고 있으며, 컬럼명에 ‘target’, ‘label’, ‘pred’ 등의 단어가 포함된 경우 자동으로 배제하도록 하여 Explicit Label Leak 패턴(Pattern A) 발생 가능성을 제거하였습니다.

데이터 누수 점검: Phase 8 코드에 대해 포렌식 감사를 실시한 결과, 주요 누수 유형들이 상당 부분 해소되었음이 확인되었습니다. 우선, 시계열 순서 누수(Pattern B)의 핵심 원인이었던 shift(-1) 연산은 여전히 타깃 생성에 활용되고 있으나, 이번에는 엄격한 시간 분할 내에서만 적용되었습니다. 즉, 동일한 Plate 내에서 이전 패스의 데이터를 이용해 다음 패스의 목표값을 설정하되, 이러한 관계가 훈련-검증 세트 간에 교차되지 않도록 설계되었습니다. 이로써 과거 Phase에서 문제가 되었던 동시에 수행된 Entry/Exit 값 혼입이 제거되었습니다. 또한 전역 통계 누수(Pattern C) 방지를 위해, 모든 통계량 계산과 전처리가 훈련 세트 기준으로만 이루어지도록 개선되었습니다. 코드상으로 RM_* 등 특수 피처에 대해 훈련 데이터의 중앙값으로만 스케일링 및 대치하고, 검증 데이터에는 그 값을 적용하거나 해당 피처를 사실상 사용하지 않도록 (USE_RM_TRAINONLY 플래그) 처리하였습니다. StandardScaler 등 데이터 스케일링 역시 fit_transform이 학습 데이터에 한정되고, 검증 데이터에는 학습 단계에서 구한 파라미터만 적용하는 형태로 구현되었습니다. 한편, Phase 8에서 데이터 중요도 가중치(Importance Weighting) 기법이나 추가적인 데이터 증강은 사용되지 않아 Pattern F (테스트 분포 활용) 가능성도 나타나지 않았습니다.

다만 세부 감사 결과, 몇 가지 잔여 리스크 요인이 관측되었습니다. 첫째, 음의 방향 시프트(shift(-1))를 통한 타깃 생성 로직은 필연적으로 데이터 구조에 복잡성을 더하며, 비록 순차 분할로 완화되었다고 해도 여전히 코드 상에서는 누수 패턴의 흔적으로 지적됩니다. 감사 도구에 따르면 119_test 스크립트에서 해당 부분이 NEG_SHIFT 이슈로 표시되었는데, 이는 이전 Phase들의 누수 발생 지점을 동일하게 포함하고 있기 때문입니다. 그러나 Phase 8에서는 이 연산이 철저히 train/test 분리 이후에 적용되므로, 성능 지표에는 부정적 영향이 없었습니다. 둘째, 하이퍼파라미터 탐색 과정에서 일부 교차검증 절차가 도입되었는데, Group K-Fold를 plate 그룹에 적용하는 등의 방법이 있었습니다. 이 경우 Fold 간에 시간순이 완벽히 보존되지 않을 수 있어 경미한 누수 가능성이 존재합니다. 예를 들어, 특정 단계에서 GroupKFold(n_splits=5)로 모델 선택을 수행한 것이 확인되었는데, 이는 Plate를 기준으로 한 교차검증이라 해도 시계열 순서와 무관하게 데이터가 혼합될 여지가 있습니다. 이러한 부분은 모델 최적화 단계에서의 참고용일 뿐 최종 성능 평가에는 직접 활용되지 않았으나, 이론적으로는 검증 세트 정보가 일부 파라미터 튜닝에 반영될 수 있는 요소입니다. 마지막으로, 아웃라이어 제거 과정이 train/test 분할 전에 데이터 전체에 대해 이루어진 점도 지적됩니다. remove_outliers() 함수를 통해 이상치 데이터를 필터링하는 로직이 E2X/X2E 전체 데이터셋에 먼저 적용되었는데, 이는 비록 비지도 학습(Isolation Forest 등) 기반이지만 테스트 부분의 분포까지 참고하여 학습 세트를 수정하는 효과를 가질 수 있습니다. 이러한 Target-Aware Filtering 유사 패턴(Pattern D)의 영향으로 극미한 데이터 정보 누출 가능성이 있으나, Phase 8의 엄격한 평가 체계 하에서는 해당 영향이 성능 지표에 유의미하게 나타나지는 않았습니다. 정리하면, Phase 8에서는 명백한 치명적 누수는 모두 제거되었고, 일부 잔여 리스크는 존재하나 모델 평가의 공정성을 해칠 정도는 아니었습니다.

그리드 서치 구현: Phase 8의 핵심 실험은 다양한 하이퍼파라미터 조합에 대한 격자 탐색(Grid Search)입니다. 코드 수준에서 이를 확인한 결과, 여러 실험 스크립트에 걸쳐 중첩 루프 혹은 반복 실행 구조로 파라미터를 변경하며 모델을 훈련하는 방식이 사용되었습니다. 예를 들어 scripts/130_test.py에서는 모델 학습률(learning_rate), 트리 최대 깊이(max_depth), 피처 선택 개수 등을 달리하며 복수의 모델을 연달아 훈련한 흔적이 나타납니다. 실험 결과 파일명을 살펴보면, 119~134번 사이 실험들은 모델 알고리즘 조합(예: 선형회귀 vs SVR, Ridge vs Lasso 등)을 바꿔가며 성능을 비교하였고, 이어서 135번 이후로는 트리 계열 알고리즘의 세부 파라미터를 조정하는 실험들이 진행되었습니다. 이러한 튜닝은 수작업 스크립트 수정과 실행을 반복한 형태로 이루어졌으며, Optuna 등의 자동화 도구는 Phase 8에서는 도입되지 않았습니다. 대신 결과 요약 파일들이 reports/summaries/ 폴더에 다수 생성되어 있으며, 예컨대 126~134 실험의 경우 E2X와 X2E 모두 SVR로 설정한 134번 실험에서 평균 Test R²가 0.1738로 해당 구간 최고치를 기록하였고, 135번 이후 LightGBM/XGBoost와 같은 트리 기반 모델로 전환된 후에도 최대 성능은 이 수준을 크게 넘지 못한 것으로 기록되어 있습니다. 각 실험 요약에는 사용된 주요 파라미터 값이 하단에 로그되는데, 감사 시 146_test_summary.txt와 149_test_summary.txt를 비교해 본 결과 max_depth=4 (실험 148 추정)와 max_depth=6 (실험 150 추정)을 사용한 두 설정의 Test R²가 모두 약 -0.103으로 거의 동일함이 확인되었습니다. 이는 트리 모델의 깊이를 달리해도 성능 변화가 미미했으며, 특정 조합에서는 오히려 음의 R² (~-0.10)로 베이스라인(평균 예측)보다 못한 결과가 나왔음을 의미합니다. 전반적으로 Phase 8 코드 구현은 이러한 다양한 시도를 체계화하여 결과를 기록하는 데 초점을 맞추었으며, 딥러닝 모델(예: LSTM) 등의 도입은 이 Phase에서는 관찰되지 않았습니다. (이전에 시도된 바 있으나 성능 및 데이터 이슈로 활용되지 않았고, Phase 8에서는 전통적 ML 알고리즘의 튜닝에 집중하였습니다.)

3. 실험 결과 및 시사점
Phase 8의 일련의 실험을 통해 모델의 실제 일반화 성능을 가늠할 수 있었습니다. 롤포워드 검증 도입 직후 평균 Test R²는 약 0.05 내외로 크게 하락하여, 이전 Phase의 높은 성능이 실제보다는 과장되었음을 입증하였습니다. 이후 진행된 수십 회의 하이퍼파라미터 탐색에서도 성능 향상은 제한적이었습니다. 대부분의 실험에서 Test R²가 -0.10에서 +0.18 사이에 머물렀고, 특히 부적절한 파라미터 조합에서는 음수의 R²를 보여주기도 했습니다. 이는 모델이 데이터 패턴을 제대로 학습하지 못하고 있음을 나타내며, 튜닝만으로 극적인 성능 개선을 이루기 어렵다는 점을 시사합니다. 실제로 Phase 8 최종 구간에서 가장 높았던 성능은 0.1832 (실험 #153) 수준으로, 이는 Phase 7에서 확인된 누수 제거 후 한계 성능과 큰 차이가 없습니다. 이를 통해 현재 사용 가능한 피처와 데이터로 달성 가능한 R² 상한선이 약 0.18 수준임이 확인되었습니다. 다시 말해, 기본적인 모델 구조를 바꾸지 않고는 추가 튜닝으로 얻을 수 있는 이득이 거의 고갈된 상태로 볼 수 있습니다. 연구팀은 이러한 결과를 종합하여, 데이터 자체의 한계에 직면했음을 인식하였습니다. Phase 8은 철저한 검증을 통해 모델의 실제 성능을 검증하고 가능한 최적의 매개변수를 세팅함으로써, 이후 단계의 방향성을 결정짓는 전환점이 되었습니다. 결국 추가적인 성능 향상을 위해서는 데이터 분포 변화 대응, 새로운 피처 발굴 또는 데이터 증강 등의 접근이 필요하다는 결론에 이르렀습니다. Phase 8의 결과는 “현 설정에서의 최적화는 완료되었다”는 사실을 보여주었으며, 이를 바탕으로 Phase 9에서는 데이터 범위 확장과 분포 보정 등의 근본적 대책을 모색하게 됩니다.
