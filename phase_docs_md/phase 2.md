# phase 2

[Phase 2] : 파생 변수(Alias) 도입에 따른 성능 왜곡 현상 분석

1. 개요 및 연구 배경

초기 베이스라인 모델 수립 이후, 데이터의 식별자 정보(Plate ID, Pass ID)를 활용하여 예측 성능을 극대화하고자 하는 시도가 있었다. 연구팀은 각 압연 판(Plate)과 패스(Pass)가 고유한 물리적 특성을 가진다는 점에 착안하여, 이를 범주형 변수 혹은 임베딩 형태의 ‘Alias Feature’로 가공하여 모델에 주입하는 실험을 설계하였다. 그 결과 Phase 2에서는 새로운 파생 변수를 추가함으로써 Test R² 지표를 단기간에 큰 폭으로 향상시키는 가시적인 효과를 확인하였다. 그러나 이러한 과도한 성능 향상은 모델 일반화 관점에서 이례적으로 높았으며, 데이터 누수 가능성에 대한 면밀한 검증이 필요한 상황이 되었다.

2. 기술적 구현 및 감사 결과

Alias 피처 엔지니어링: scripts/010_experiment.py 코드 분석 결과, 판 번호와 패스 번호를 category.cat.codes로 변환하여 학습 피처로 강제 주입하는 로직이 추가되었다. 즉, 기존에는 모델 학습에서 제외되던 식별자 정보를 인위적으로 특징 공간에 포함시켜, 각 판별 개체에 고유한 ID 특성을 부여한 것이다. 이 구현으로 Train 데이터에 대해 모델이 손쉽게 식별자별 정답을 암기하게 되었으며, 실제 010 단계 요약에서 XGBoost 모델의 Train R²가 1.0에 수렴하는 현상이 확인되었다.

데이터 누수(Leakage) 식별: 해당 Alias 기법 도입 코드를 포렌식 감사 프로토콜에 따라 점검한 결과, 치명적인 데이터 누수 패턴이 다수 발견되었다.

상세 원인: 특히 scripts/011_003_r2_uplift_suite_2.py 등에서 Importance Weighting 모듈이 활성화되어 있었다. 이는 compute_importance_weights 함수 호출 시 Train 데이터와 Test 데이터를 명시적으로 결합한 뒤 도메인 분류기를 학습하여 가중치를 산출하는 방식으로, Test 셋의 분포 정보가 모델 학습 단계에 유입되는 Pattern C (Transductive Leak) 유형의 누수를 초래하였다. 해당 함수는 Train/Test 구분 레이블을 예측하도록 XGBoost 분류기를 학습함으로써 훈련 단계에서 이미 Test 분포를 활용하고 있었으며, 이로 인해 모델이 검증 단계 이전에 정답지 힌트를 얻는 결과를 낳았다.

추가 결함: 또한 scripts/012_003_r2_uplift_suite.py 코드에서는 시계열 특성 생성 과정에서 shift(-1) 연산이 Plate 구분 없이 적용되는 오류가 있었다. 그 결과 동일 판내 연속 패스의 Exit 값을 Entry 행의 피처로 잘못 가져오는 Pattern B (Sequence Leak)가 발생하였다. 이 버그로 모델은 현재 패스의 입력 피처에 다음 패스의 실제 목표값 일부를 포함시키는 심각한 데이터 누수를 일으켰던 것으로 파악된다.

변동 실험 플래그: 아울러 코드에는 Alias 효과를 검증하기 위한 다양한 플래그(S0, S1 등)를 토글하는 실험 설정이 존재하였다. 예컨대 scripts/012_experiment.py에서 USE_S1 플래그를 켜고 끔에 따라 Stratified Group Split 적용 여부를 비교하였는데, 이 때 Test R²가 약 0.66에서 0.79로 변화하였다. 이러한 큰 편차는 Alias 피처의 효과가 데이터 분할 방식에 따라 불안정하게 달라짐을 보여주며, Alias 전략이 모델 일반화에는 일관된 기여를 하지 못함을 시사한다. 결과적으로, 해당 Phase의 구현은 성능 향상을 위한 아이디어였으나 다수의 누수 요소가 포함되어 있었고, 코드 감사 결과 데이터 정합성 측면의 심각한 문제점들이 확인되었다.

3. 실험 결과 및 시사점

성능 지표의 비정상적 급등: Alias 피처 도입 직후 실행된 010 단계 실험에서 Test R²가 0.9522까지 상승하며 이전 Phase 대비 두 배 이상 높은 수치를 기록하였다. 표면적으로 모델 예측력이 크게 향상된 것처럼 보였으나, 앞서 식별된 누수 요인들로 인해 이러한 성능은 실체 없는 거품인 것으로 드러났다. 실제로 후속 실험(012~013번)에서 일부 누수 경로를 차단하거나 설정을 변경하자 Test R²가 0.66~0.79 수준으로 급락하였는데, 이는 초기의 높은 R² 수치가 데이터 누수 및 과적합에 기인한 허수였음을 방증한다.

결론: Alias 기반 식별자 피처의 도입은 모델의 물리적 패턴 학습을 돕기보다는, 훈련 데이터의 고유 ID와 정답을 연결짓는 치트 키 역할을 한 것으로 평가된다. 본 Phase에 대한 감사 결과를 종합하면, 모델 향상으로 보였던 성능 개선은 대부분 데이터 누수를 통해 얻어진 인위적인 상승이었다. 이에 따라 연구팀은 해당 접근법의 현업 적용 가능성을 부정하고, 다음 Phase에서는 철저한 누수 차단 기법(Leak Guard 모듈 등)의 도입을 통해 모델의 신뢰성을 재검증하는 방향으로 전략을 선회하였다.
