# phase-2

[Phase 2] : 데이터 누수 포렌식 감사 및 베이스라인 정화

1. 개요 및 연구 배경 (Executive Summary)

직전 Phase 1의 베이스라인 모델은 평균 Test R² 약 0.4174 수준에서 정체되어 있었다[1]. 특히 X2E 방향(출측 예측)의 성능 편차가 컸으며, 무작위 롤포워드 검증에서도 R² ≈ 0.4963으로 낮은 일반화 성능을 보였다[2]. 이러한 성능 정체와 분포 차이의 원인을 분석하던 중, Phase 2 실험에서는 돌연 Test R²가 0.9522까지 치솟는 비정상적 결과가 관찰되었다[3]. 시계열 데이터의 불확실성을 고려하면 0.95라는 수치는 현실적으로 불가능한 수준이며, 연구팀은 이를 모델 구조 개선의 성과가 아니라 데이터 누수(data leakage)로 인한 허위 과적합으로 판단했다.

Phase 2의 기술적 가설은 두 갈래였다. 첫째, Label 누수 – 타깃 변수 또는 그 함수가 피처에 직접 혹은 간접적으로 포함되어 정답을 미리 알려주는 상황이 의심되었다. 둘째, 시계열 누수 – 데이터 전처리 과정에서 미래 정보가 현재 학습에 혼입되었을 가능성이 제기되었다. 예를 들어, 플레이트(Plate) 간 연속 패스 데이터를 병합하며 발생하는 index shift나, Train/Test 분할 이전에 전체 데이터에 대한 통계치를 활용한 변환 등이 누수 경로일 수 있다는 가설이다[4].

이에 Phase 2의 목표는 포렌식 코드 감사를 통해 이러한 누수 경로를 식별하고, 모델링 파이프라인을 전면 수정하여 신뢰 가능한 베이스라인 성능(Sanitized Baseline)을 재정립하는 것이었다. 성공 기준은 Permutation 검증과 시계열 Roll-forward 검증에서 누수 징후가 전무한 모델을 구축하는 것이다.

2. 상세 기술적 구현 및 감사 결과 (Detailed Technical Audit)

2.1. 주요 코드 변경 사항 및 구조적 진화 (Key Code Evolution)

Phase 2에서는 코드 구조가 근본적으로 재설계되었다. 가장 큰 변화는 Train/Test 분할 시점의 이동이다. 기존 코드(scripts/010_..._suite.py)에서는 특성 생성과 이상치 제거가 데이터 전체에 대해 수행된 후 Train/Test를 분할하였다[5]. 예를 들어, base_feature_engineering → remove_outliers_simple → add_sequence_lags 순으로 전처리를 완료한 후에 split_by_anchor로 데이터를 나누는 흐름이었다[5][6]. 이러한 구조에서는 테스트 데이터의 분포 정보가 전처리에 반영되어, 평균 및 분위수 계산 등에서 Transductive 누수가 발생할 위험이 있었다.

Phase 2 후기 코드(scripts/012_..._suite.py 및 015_..._suite.py)에서는 이를 거꾸로 재구성했다. 먼저 split_by_anchor 함수를 통해 플레이트 그룹 단위로 Train/Test를 분할한 뒤[7], Train 세트에 한정하여 특성 공학을 적용하고 동일한 변환을 Test에 매핑하는 방식으로 변경되었다[8]. 구체적으로, prepare_train_test_leak_safe 프로시저 내부에서 원시 데이터를 tr_raw(Train)와 te_raw(Test)로 나눈 후, 각각 별도의 base_feature_engineering과 add_sequence_lags를 적용했다[8]. 이를 통해 모든 파생변수 생성과 정규화가 Train 기준으로만 학습되고, Test에는 학습된 파라미터를 그대로 적용하는 구조적 누수 차단이 이루어졌다[9].

이상치 처리 로직도 대폭 수정되었다. 이전 버전의 remove_outliers_simple 함수는 전체 데이터에서 타깃 분포의 0.5% 극단치를 제거하는 방식이었다[10]. 이로 인해 Test 셋의 극단값 몇 개가 아예 제거됨으로써 모델 평가지표가 인위적으로 상승하는 문제가 있었다. 실제로 Phase 2 초기 실험에서 Train R²=1.0, Test R²≈0.95로 치솟은 원인 중 하나는 Test 데이터의 어려운 샘플(outlier)을 사전에 제거했기 때문으로 파악되었다. 수정된 코드에서는 Train 세트에서만 이상치 판단 기준을 구하고(compute_train_outlier_bounds), Train에서는 해당 범위를 벗어난 샘플을 제외하되 Test 세트에서는 행을 삭제하지 않고 동일 기준으로 Feature 값만 클리핑하는 방식으로 변경되었다[11]. 예를 들어, Train에서 워핑 지수(_target)의 0.5%~99.5% 범위가 [-30, 30]이라면, Test의 워핑 지수가 이 범위를 벗어나더라도 행을 제거하지 않고 ±30으로 절삭하도록 구현되었다. 이를 통해 Test 분포의 본질적 난이도는 유지한 채 극단치로 인한 모델 불안정만 완화하도록 했다.

또한 중요도 가중(Importance Weighting, IW) 기능의 구현이 누수 안전하게 개선되었다. 기존에는 Train과 Test 데이터를 합쳐 로그istic 분류를 학습함으로써 샘플 가중치를 추정했는데[12], 이 방식은 Test 피처 분포를 학습에 활용하는 전형적인 transductive 누수이다. Phase 2 수정 코드에서는 IW_MODE = "oof" 설정을 도입하여, 반드시 Train 데이터에 대해서만 OOF 방식으로 중요도 가중을 계산하도록 강제했다[13]. 실제 코드에는 if IW_MODE != "oof": raise RuntimeError("[LEAK-GUARD] Importance weighting must be OOF-only ...")와 같은 강제 예외 처리가 추가되어, 실수로 이전 방식("test" 모드)을 사용할 경우 바로 실행이 중단되도록 방어막을 쳤다[14]. 이와 함께 Stratified Split(S1), Target Encoding(TE2) 등 각 전략 플래그 역시 OOF나 Train 전용 방식으로 구현되어, 자기 자신(target)의 정보가 피처에 유입되지 않도록 일관되게 관리되었다[9].

마지막으로, 시퀀스 랙(Sequence Lag) 처리와 교차 앵커링(Anchor) 관련 코드가 세분화되었다. 이전까지 lag 피처 추가는 기본값으로 항상 수행되었으나, Phase 2 후반부에서는 SEQ_LAG 플래그(L1)를 별도로 두어 랙 사용 여부를 실험별로 조정할 수 있게 했다[15]. 이를 통해 랙 피처가 성능에 미치는 영향과 잠재적 누수 기여도를 독립적으로 평가할 수 있었다. 실제로 누수 감사 단계에서 S0 (Baseline) 대비 S0+L1 (랙 포함) 실험을 비교하여 랙 추가가 성능에 기여하는 정도를 계량화했다. 한편 Anchor 정책도 환경변수를 통해 유연하게 관리되었다. Phase 2에서는 한 번 분할한 Train/Test 플레이트 목록(Anchor)을 고정하여 다른 실험 간 동일한 데이터 분할을 재현하거나, 과거 Phase(예: Phase 1의 Cross 방식)에서 사용된 분할을 강제로 적용하는 기능(ANCHOR_FROM_CROSS)이 추가되었다[16]. 이는 다양한 분할 전략 하에서 모델을 재평가함으로써, 성능 변화의 원인이 데이터 분할 방식에 기인하는지 여부를 교차 검증하기 위한 장치였다.

2.2. 데이터 누수 및 정합성 포렌식 (Forensic Leakage Audit)

Phase 2 코드에 대한 포렌식 감사 결과, 여러 유형의 누수 패턴이 식별되었다.

패턴 A – 라벨 누수 (Label Leakage): 직접적인 타깃 유출은 발생하지 않은 것으로 판단되었다. 코드 상에서 타깃 컬럼 warping_index_target은 EXCLUDE 리스트에 포함되어 모든 피처셋에서 제거되고 있었고[17], Target Encoding 역시 K-Fold OOF로 진행되어 자기 자신의 값을 참조하지 않도록 구현되었다. 따라서 타깃값 그 자체가 피처로 들어가는 경우는 없었다.

패턴 B – 시퀀스 누수 (Future Information): 치명적인 미래 정보 혼입이 과거 코드 조각에서 발견되었다. 003번 실험 코드를 추적한 결과, 플레이트 데이터를 병합하는 과정에서 df.groupby(PLATE_COL)["warping_index"].shift(-1) 연산이 사용된 부분이 있었다[4]. 이는 각 판의 행을 한 칸 앞으로 밀어 다음 패스의 워핑 지수를 현재 행에 추가하는 로직으로, Entry/Exit 구분 없이 병합하면 출측(pass n의 결과)이 곧바로 다음 행의 입력 피처로 포함되는 문제가 있었다. 실제 누수 감사 로그에서도 해당 코드가 Issue 코드 NEG_SHIFT로 지목되었다[4]. 다행히 Phase 2 주력 코드에서는 E2X와 X2E를 분리 처리하여 이러한 문제가 해소되었으나, 이 발견을 통해 미세한 시계열 누수 가능성까지 면밀히 검토하게 되었다. 예컨대, lag 피처 생성시에도 그룹 경계를 엄격히 지켜 다른 플레이트나 미래 패스의 정보가 섞이지 않도록 모든 shift(1) 연산에 plate 그룹 기준이 적용되었음을 확인했다.

패턴 C – Transductive 누수 (시험 데이터 정보 사용): 다수의 요소에서 Train 외 데이터 활용이 드러났다. 첫째, 앞서 언급한 대로 이상치 제거 단계에서 Test의 분포를 고려한 점이 가장 큰 누수 요인이었다[10]. Train/Test 구분 없이 전 데이터의 분위수를 계산함으로써, 모델이 테스트셋의 타깃 분포 범위를 미리 알아버린 격이 되었다. 둘째, Stratified Split(S1) 자체도 누수 가능성을 내포한다. S1 전략은 쌍(pair) 단위 타깃 분포의 유사도를 최대화하도록 Train/Test를 분할하는데, 구현상 GroupShuffleSplit.split(X, y, groups)에서 타깃 벡터 y가 입력되어[18], 테스트셋의 타깃 분포를 고려한 샘플링이 이루어진다. 이는 타깃값 자체를 모델에 주는 것은 아니지만, 평가 시나리오를 지나치게 낙관적으로 만드는 요소다. 감사 결과 S1을 적용한 010번 실험이 미적용 대비 Test R²를 0.91→0.95로 끌어올렸지만[3], Strict 롤포워드 평가에서는 오히려 성능이 크게 저하된 것으로 나타났다(자세한 수치는 다음 절에 분석). 이를 통해 목표 변수를 이용한 데이터 분할 또한 잠재적 누수임을 인지하였고, Phase 2 이후로는 시간 순서 고정 검증을 기본 원칙으로 삼게 되었다. 셋째, 중요도 가중(IW)의 구버전 구현이 문제였다. 앞서 확인된대로, Train+Test 혼합 데이터에 분류기를 학습시켜 샘플 가중치를 계산한 것은 시험 데이터의 특징분포 정보를 모델 학습에 사용한 것이나 다름없다. 이는 Phase 2 중반까지 성능 향상에 기여했으나, 엄밀한 의미에서 데이터 누수로 규정되어 Phase 2 후반 코드에서 강제로 차단되었다[13].

요약하면, Phase 2 감사에서는 의도치 않은 시험정보 유출이 다수 발견되어 대부분 코드 레벨에서 “유죄(Guilty)” 판정을 받았다. 다만, 타깃의 직접적인 피처 유입이나 메타정보 누출 등 특정 컬럼 차원의 누수는 없었고, 대부분 절차상의 누수(작업 순서, 데이터 분할 방식)로 판명되었다. 이러한 발견을 바탕으로, Phase 2 후반 코드는 앞서 기술한 여러 구조 개선을 통해 모든 누수 경로를 원천 봉쇄하도록 리팩토링되었다. 그 결과, 누수 감사 도구로 재검증한 결과 Phase 2 최종 코드(016_v3)에는 더 이상 Issue 코드가 발생하지 않았으며, Permutation Test에서도 이상 신호가 없는 것으로 확인되었다.

2.3. 실험 설정 및 플래그 분석 (Configuration Analysis)

Phase 2에서는 다양한 전략 플래그(Strategy Flags) 조합을 통해 모델 성능 변화를 실험하였다. 주요 플래그의 의미와 누수 방지 방식은 다음과 같다.

S0 (Baseline): 가장 기본 설정으로, SelectKBest로 상위 120개 피처 선택, Plate-Group 기준 랜덤 분할이 적용된 모드이다[19][20]. S0 자체는 특별한 기법을 포함하지 않지만, Phase 2 초기 코드에서는 기본적으로 시퀀스 랙 피처가 포함되어 있었다. Phase 2 후기 코드에서는 S0에서 랙을 제외하고, 필요 시 명시적으로 S0+L1 형태로 사용하도록 변경되었다. Baseline의 의미는 “어떤 특수 전략도 적용하지 않은 모델”이며, 누수 차단 이후 이 S0 모델이 사실상 의미있는 예측력을 잃었음이 드러났다(후술).

S1 (Stratified Split): 앞서 언급한 타깃 분포 균등화 분할 모드이다[18]. 동일 Plate 그룹 내 연속 패스쌍(pair)의 Δ타깃 분포를 기준으로 Stratified GroupShuffleSplit을 수행한다. 목적은 Train/Test 간 분포 차이를 줄여 모델이 학습하기 용이하도록 하는 것이었지만, Phase 2 결과는 이로 인해 평가 환경이 지나치게 쉬워지는 부작용을 보여주었다. 실제 S1 적용 시 평균 Test R²는 0.95로 급등했으나, 이는 누수 효과로 판명되었다. 현재는 해당 플래그를 폐기하고, 시간순 분할(Strict Roll-forward)로 대체하였다.

TE2 (Pair Target Encoding): 인접 패스쌍의 식별자(예: “1→2”, “2→3”)를 타깃 통계로 인코딩하여 피처로 추가한다[20]. Phase 2에서는 Δ타깃(출측-입측 차이)의 평균을 encoding하는 방식을 도입했다. 중요한 것은 K-Fold OOF 방식을 사용하여 encoding 값이 산출되었다는 점이다[21]. 각 폴드의 Train에서 해당 pair의 평균 Δ를 계산해 Test fold에 적용함으로써, 해당 샘플의 진짜 타깃값이 encoding에 쓰이지 않도록 했다. 이로써 TE2 자체는 누수 없이 구현되었으며, Phase 2 후반 TE2를 재도입한 실험(017_v2 S0+TE2)에서 성능 향상 효과를 검증하게 된다.

W2 (Heteroscedastic Weighting): 각 패스쌍마다 Δ타깃의 분산을 추정하여 가중치를 부여하는 기법이다[20]. Phase 2에서는 OOF 방식으로 쌍별 표준편차를 구하고, 표본 크기에 따라 EB(shrinkage)을 적용한 안정화 표준편차를 산출한 뒤, Train의 각 샘플에 $w_i = \frac{\sigma_{\text{global}}}{\hat\sigma_{pair(i)}}$의 가중치를 부여했다[22][23]. 이 역시 Train 내부 교차검증을 통해 추정 후 Test에 적용하여, Test의 분산 정보 유출을 막았다. 해당 기법은 Δ분포가 큰 패스(예: 1→2)의 샘플은 낮은 가중치를, 안정적인 패스(예: 5→6)의 샘플은 높은 가중치를 부여함으로써 불균일한 예측 오차 분포를 보정하려는 목적이었다.

T2 (Δ-Target Regression): 현재 패스의 결과를 다음 패스의 입력으로 활용하는 물리적 관계를 반영하기 위해 도입된 설정이다[20]. 구체적으로, 모델의 예측 대상(target)을 $y_{\text{next}} - y_{\text{current}}$로 두어 잔차(Δ)를 학습하게 하고, 최종 예측시 현재 패스의 실제 측정치($y_{\text{current}}$)를 더해 다음 패스 값을 산출하도록 했다. 이렇게 하면 모델이 직접 절대적인 출측 값을 맞히기보다 증분 변화량에 집중하게 되어 학습이 안정화될 수 있다. Phase 2에서는 해당 아이디어의 타당성을 파일럿으로 시험했으며, Δ-Target 변환 자체는 누수와 무관하게 적용 가능하다. 다만, $y_{\text{current}}$ 값이 실제 운영에서는 unknown일 수 있어, 향후 Phase에서 이 개념은 2-스텝 모형(Residual Stacking) 형태로 발전된다.

이외에도 Phase 2에서는 R1 (Robust Loss), M2 (Monotone Constraint), SEG (Phase Segmentation) 등의 옵션이 있었으나, 본 Phase의 핵심은 아니므로 자세한 설명은 생략한다. 중요한 점은, Phase 2를 거치며 모든 설정 플래그가 누수 방지 관점에서 재평가되었고, 필요시 코드 수준에서 강제 체크를 추가하여 (예: IW_MODE, PERMUTE_TARGET 등) 실험 진행 중에라도 누수 발생 시 바로 탐지할 수 있게 만들었다는 것이다.

3. 실험 결과 및 데이터 분석 (Performance Analysis)

3.1. 정량적 지표 변화 (Quantitative Performance Evolution)

Phase 2 전후로 모델 성능 지표는 극적인 변화를 겪었다. 누수 차단 전 단계에서 XGBoost+RF 모델의 평균 Test R²는 0.9522로 이 분야 데이터에서 관측된 바 없는 높은 수치를 보였다[3]. 그러나 누수를 차단하고 동일 모델을 재평가한 결과, Test R²는 -0.0835 수준까지 급락하였다[24]. 이는 약 90%p 이상의 감소로, 초기 모델이 학습한 “패턴”의 대부분이 실제 예측력 있는 신호가 아니라 데이터 누수에 기인한 환상이었음을 방증한다. 특히 Phase 2 최종 베이스라인(r2_uplift_alias_v3 S0)은 E2X 방향 Test R² -0.8469, X2E 방향 -0.1391로 집계되어 평균 -0.4930을 기록했는데[25][26], 이 수치는 모델이 평균보다도 못한 예측을 했음을 의미한다. 달리 말해, 누수 제거 후에는 모델이 오차가 큰 무용지물 예측기가 되었음을 의미한다.

Train 데이터 성능과의 격차도 주목할 만하다. 누수 제거 전에는 Train R²=1.000에 가까우면서 Test R²도 0.9 이상으로 높았지만[3], 제거 후에는 여전히 Train R²≈1.0인 반면 Test R²≒0으로 추락하여 극단적인 일반화 성능 저하(Generalization Gap)가 드러났다[27]. 이는 이전에는 누수로 인해 Test 데이터까지 사실상 정답지를 보고 맞춘 것과 같았으므로 Train/Test 차이가 작게 나타났던 반면, 이제는 모델이 실제 패턴을 못 찾아 Train에 과적합하고 Test에는 실패하고 있음을 나타낸다. 이와 함께 X2E 방향의 성능이 E2X보다 일관되게 높았던 현상도 사라졌다. 초기에는 X2E Test R²가 0.95까지 올라 E2X(0.87)를 상회했는데[28], 이는 이웃하는 패스 간 물리적 연관성 덕분에 얻은 (혹은 누수로 부풀려진) 성능으로 추정된다. 누수 제거 후에는 두 방향 모두 유의미한 예측력을 보이지 못하게 되어, 이제 데이터 그 자체의 한계와 문제 구조의 난이도가 드러났다고 하겠다.

흥미롭게도, Phase 2 중간 단계에서 일부 합법적인 성능 향상 요소도 관찰되었다. 예를 들어 시퀀스 랙(L1) 피처를 포함한 실험에서는 누수 차단 후에도 Test R²가 약 0.66 수준까지 상승했다[29]. 앞서 누수 감사에서 확인했듯 랙 피처 자체는 미래 정보를 참조하지 않고 이전 패스의 결과만 이용하므로 합법적인 신호이다. 실제 Phase 2의 통제 실험에서 S0 (랙 미포함) 대비 S0+L1 (랙 포함) 모델은 큰 차이를 보였는데, 누수 제거 후에도 0에 수렴했던 R²가 랙 하나로 0.66까지 회복된 것은 연속 공정 간의 인과 연결성이 모델에 유효한 정보를 제공함을 의미한다. 반대로 S1 (타깃 분포 균등 분할)은 제거 후 완전히 효과를 잃었으며, TE2와 W2 등의 기법은 오히려 Phase 3 이후에야 다시 활용할 수 있는 발판이 마련되었다. 종합하면, Phase 2에서는 성능 지표상 거품을 제거하고 바닥을 드러냈다고 볼 수 있다. 수치적으로는 퇴행이지만, 이는 모델이 착시 효과 없이 객관적인 난이도 위에서 평가되기 시작했다는 점에서 의미 있는 성과이다.

3.2. 통계적 검증 및 로그 포렌식 (Statistical Verification & Log Forensics)

누수 수정의 효과는 다양한 통계적 테스트를 통해 검증되었다. 우선 타깃 퍼뮤테이션 테스트(Permutation Test) 결과가 극적으로 개선되었다. 누수 의심 단계에서 실행된 퍼뮤테이션 실험(실험 ID 014)은, 타깃을 무작위로 섞었음에도 Test R²가 0.9216에 달했다[30]. 즉 모델이 목표변수와 아무 상관도 없는 랜덤 노이즈로도 높은 설명력을 보인 것으로, 데이터 누수의 존재를 강하게 시사했다. 그러나 Phase 2 최종 코드로 동일한 퍼뮤테이션 검증(실험 ID 016)을 수행하자 평균 Test R²가 -0.4930으로 급격히 하락했다[31]. E2X와 X2E 개별로도 각각 -0.8469, -0.1391로 0 부근 (오차범위 내) 또는 그 이하 값을 나타냈다[27]. 이는 모델이 임의 섞은 타깃에 대해 어떤 유의미한 패턴도 학습하지 못했다는 뜻이며, 누수가 완전히 제거되어 무작위 데이터에는 당연히 성능이 0에 수렴해야 하는 정상 상태를 회복했음을 의미한다. 요약하면, Phase 2 전후 퍼뮤테이션 R²가 0.92 → -0.49로 극명히 대조되어, 누수 차단의 효과를 통계적으로 입증했다.

또 다른 검증으로, Strict Roll-forward R² 지표를 관찰하였다. 이는 시간 순서를 엄격히 보전한 평가로, 실제 운영 환경에 보다 가까운 지표다. Phase 2 이전에는 일반 Test R²만 보고 성능이 높다고 착각할 뻔 했지만, 엄밀한 롤포워드 평가에서는 이미 음수의 R² (-0.7242)로 모델 붕괴 조짐이 나타나고 있었다[32]. Phase 2 이후 개선된 모델의 Strict Roll-forward R² 역시 약 -0.6185로 나타났는데[33], 이는 이제 일반 Test R²와 Strict R²가 모두 0 근처로 수렴하여 평가 기준 간 일관성이 확보되었음을 보여준다. 달리 말해, 과거에는 랜덤 분할 평가만 보면 모델이 훌륭해 보였으나 실제 시계열 적용시 성능이 처참했던 반면, 이제는 어떠한 평가를 해도 일관되게 “예측 불가” 수준으로 바닥을 찍었으므로, 향후 진짜 성능 향상은 이 바닥에서부터 시작하면 된다.

Phase 2에서는 데이터 분포 분석도 심층적으로 수행되었다. 특히 각 패스 전후의 워핑 지수 변화분(Δ) 분포를 Pass별로 비교한 결과, 통계적으로 유의미한 분포 차이 (distribution shift)가 확인되었다. 예를 들어 1→2패스와 5→6패스의 Δ분포를 비교하면 표준편차 비(max/min)가 1.775에 달했고, Kruskal-Wallis 검정 p-value가 1.28e-74로 계산되었다[34]. p<0.001 수준을 훨씬 넘어서는 이 값은 “모든 패스의 분포가 동일하다”는 귀무가설을 강하게 기각한다. 즉 패스 번호에 따라 워핑 변화 양상이 크게 다르므로, 하나의 모델로 전체 패스를 일괄 예측하는 현재 프레임워크에 한계가 있음을 의미한다. 이러한 분석은 Phase 1에서도 일부 진행되었지만 Phase 2에서 더욱 집중적으로 이루어졌고, 덕분에 Phase 3에서 패스별 트렌드 보정(Detrending)이나 페어별 모듈화(Segmentation)와 같은 전략의 필요성이 대두되었다. 실제로 Phase 2 로그의 Δ-분석 상위쌍을 보면 1→2패스의 평균 Δ가 -29.217 (대폭 감소)인 반면 5→6패스는 -6.84로 변동 폭이 작았다[34]. 이는 초기 패스에서 판의 휨이 크게 교정되고 후반에는 미세 조정되는 물리적 특성을 반영하며, 모델링 시 초기 패스와 후반 패스를 동일한 입력공간(feature space)에서 다루는 것이 비효율적임을 시사한다.

마지막으로, Phase 2에서는 모델의 잔차 분석이 사실상 의미를 잃었으므로 간략히 언급한다. 누수 제거 후 모델 잔차에는 뚜렷한 패턴이 없었고, 잔차의 자기상관이나 피처 상관 역시 유의미하지 않았다. 오히려 Phase 2의 시사점은 “모델이 학습한 것이 없다”는 한 마디로 요약되며, 이는 오히려 다음 Phase에서 추가적인 구조적 변화를 통해 학습할 유의미한 신호를 주입해야 할 필요성을 강조해주었다.

4. 결론 및 향후 계획 (Conclusion & Future Work)

Phase 2를 통해 데이터 파이프라인의 무결성(Data Integrity)을 확보하는 데 성공했다. 비록 수치상 성능 지표(Test R²)가 0 수준으로 급락하여 모델이 무용지물처럼 보이지만, 이는 과도하게 부풀려졌던 거품을 걷어낸 정화 과정으로 평가할 수 있다. 이제야말로 모델의 참된 실력을 논할 수 있는 기반이 마련된 셈이다. 이번 Phase의 결과를 종합 평가하면 다음과 같다.

4.1. 종합 평가: Phase 2의 핵심 성과는 “모델을 못 맞추게 만든 것”이다. 언뜻 역설적이지만, 이는 성능 지표의 신뢰성 회복을 의미한다. 이전까지 높게만 나오던 R²가 -0.08까지 떨어진 것은 그간 모델이 실력 이상으로 점수를 받아왔음을 보여준다. 따라서 수치적으로는 퇴보했으나, 데이터 누수를 완벽 차단했다는 점에서 Phase 2는 성공적이었다고 평가된다. 또한 이 과정을 통해 우리 모델이 풀어야 할 문제가 얼마나 어려운지 재확인하였고, 향후 전략 수립에 현실적인 기준점을 얻었다. 요컨대, Phase 2는 “모델이 진정 무엇을 모르는지”를 알게 해준 중요한 교정 단계였다.

4.2. 핵심 시사점: 이번 연구로 얻은 기술적 인사이트는 다음과 같다.

평가 기법의 중요성: 랜덤 분할의 높은 성능은 착시일 수 있으며, 시계열 Roll-forward 검증이 필수임을 재확인했다. 미래 데이터 유입이 없는 엄격한 평가에서만 모델의 일반화 성능을 정확히 측정할 수 있다.

데이터 전처리 순서: Train/Test 분할은 가능한 한 이른 시점에 수행해야 한다는 교훈을 얻었다. 분할 이전에 계산된 통계량(평균, 표준편차 등)은 모두 누수 요인이 될 수 있으므로, 표준화(정규화)나 필터링은 반드시 Train 기반으로 fit하고 Test에는 적용만 해야 한다는 원칙을 구현으로 입증했다.

누수 감지 자동화: Phase 2에서 도입한 Permutation 자동 검증 모드는 유용한 누수 탐지 도구로 작동했다. 특히 Permutation시 R²≠0이면 즉각 알람을 주는 체계를 갖춤으로써, 향후 실험에서 누수가 재발생하더라도 초기에 발견하여 대응할 수 있을 것으로 판단된다[35].

4.3. 향후 연구 방향: Phase 2 종료 시점에서 모델은 유의미한 예측력을 상실한 상태였다. 이는 현재의 단일 패스 기반 접근법만으로는 압연 공정의 복잡한 변동성을 설명하기 어렵다는 것을 의미한다. 따라서 다음 Phase에서는 복수 패스 간의 상호 의존성(Inter-pass dependency)을 본격적으로 활용하는 방향으로 전환할 계획이다. 구체적으로, Phase 3에서는 Entry-Exit 교차 예측 프레임워크를 재도입한다. Phase 1에서 시도되었던 E2X/X2E 교차모델을 한층 개선하여, 출측 예측값을 다음 패스의 입력 피처로 연결하거나, 패스 번호에 따른 트렌드 보정(detrending) 및 도메인 분할 기법을 접목할 예정이다. Phase 2에서 확인된 분포 차이를 완화하기 위해 판별적 도메인 적응(Importance Weight OOF)과 Expanding Mean Normalization 같은 기법도 병행할 것이다. 요약하면, Phase 3의 목표는 “누수 없는 깨끗한 데이터 위에서, 어떻게 다시 성능을 끌어올릴 것인가”에 있다. Phase 2가 만들어준 청정 기반 위에서, 보다 정교한 구조와 피처링으로 잃어버린 R²를 되찾는 작업이 뒤따를 것이다. (끝)[34][30]
