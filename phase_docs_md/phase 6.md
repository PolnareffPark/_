# phase 6

[Phase 6] : 교차모델 이상치 발생과 긴급 수정

1. 개요 및 연구 배경
Phase 5에서 교차 전이 예측모델의 성능이 안정화되어 가던 중, Phase 6 초반 084번 실험에서 비정상적으로 높은 테스트 R²(0.9142)가 관측되었다. 이는 이전 평균 대비 3배에 달하는 급등으로서, 연구팀은 모델의 실제 향상이 아니라 데이터 누수 또는 코드 오류에 의한 허수 가능성을 강하게 의심하였다. 이에 따라 비정상 성능의 원인 규명과 모델 신뢰도 회복을 위한 긴급 감사 및 수정 작업이 Phase 6 전체에 걸쳐 수행되었다.

2. 기술적 구현 및 감사 결과
 교차모델 코드 결함 식별: scripts/084_test.py 코드 분석 결과, Entry 데이터와 Exit 데이터가 혼합되는 버그가 발견되었다. 특히 교차 전이 예측 루틴에서 인덱스 처리 오류로 현재 패스(t)의 학습 특성에 다음 패스(t+1)의 정보가 잘못 투입되고 있었으며, 이는 Pattern E (Cross-Reference Leak) 유형의 전형적인 데이터 누수에 해당한다. 이 결함으로 모델이 미래 데이터의 정답을 미리 참조하여 학습하는 상황이 초래되었다.
 버그 수정 조치: 해당 누수 버그는 즉시 파악되어 scripts/085_experiment.py에서 코드가 교정되었다. 잘못된 인덱스 참조 부분에 미래 데이터 접근을 차단하는 조건문 등이 추가되어, t+1 패스의 어떠한 정보도 t 패스 학습에 사용되지 않도록 로직을 수정하였다. 수정된 코드 실행 결과, 084번의 비정상 R²가 085번 실험에서 0.23 수준으로 급락하여 정상 범위로 돌아왔다. 이후 동일한 조건의 086~088번 실험을 연이어 수행한 결과 모두 Test R² ≈ 0.2313으로 동일하게 나타나 누수가 재발하지 않았음을 확인하였다.
 교차 로직 V2 도입: 089번 실험부터는 파일명에 __V2가 붙은 개선된 교차모델 모듈이 도입되었다. scripts/089_test.py 등 V2 버전 코드에서는 Entry→Exit 예측 정보를 처리하는 방식을 리팩토링하여, 별도의 데이터 복사본을 활용함으로써 원본 데이터셋 오염을 방지하였다. 즉, 한 방향의 예측치를 다른 방향의 모델에 전달할 때 원본 훈련 데이터에 반영하지 않고 별도 구조로 관리함으로써, 084번에서 발생한 유형의 교차 데이터 누수가 원천 차단되도록 구현되었다.
 검증 프로토콜 강화: 본 사건 이후 연구팀은 매 실험마다 자동 누수 감사 지표인 퍼뮤테이션 R²(LEAK_AUTOCHECK)를 더욱 면밀히 점검하는 등 검증 프로토콜을 강화하였다. 084번 실험 당시에도 permuted R²는 ~0 수준(정상치)이었으나, 실제 성능 지표가 비정상적으로 높다는 점 자체가 중요한 경고 신호였다. 이 교훈을 바탕으로 팀은 향후 예상 밖의 고성능 결과에 대해 즉시 누수를 의심하고, 코드와 데이터를 철저히 감사하는 원칙을 재확립하였다.

3. 실험 결과 및 시사점
 이상 성능 지표 관측: 교차모델 누수 버그로 인해 084번 실험에서 Test R²=0.9142라는 비현실적으로 높은 수치가 나타났다. 이는 모델 일반화 성능이 급향상된 것이 아니라, 잘못 유입된 미래 데이터로 사실상의 정답 맞추기를 한 결과였다.
 누수 차단 후 정상화: 결함 수정 직후 시행된 085번 실험에서 Test R²가 0.23 수준으로 정상화되었다. 성능 지표의 급락은 앞선 고성능이 허상임을 입증하는 동시에, 누수 차단 조치의 효과를 보여준다. 이후 086~088번의 반복 실험에서도 동일한 R² (~0.2313)이 지속되어 결과의 일관성과 재현성이 확보되었다. 나아가 교차 로직을 개선한 089~091번 실험들에서도 Test R² 0.21~0.26 범위의 안정적인 성능이 확인되며, 초기 이상치 현상은 완전히 해소되었다.
 결론 및 향후 계획: 본 Phase에서는 치명적 데이터 누수를 신속히 발견하고 교정함으로써 모델 성능 지표의 신뢰도를 회복하였다. 이 과정에서 누수 방지의 중요성을 재인식하여, 향후 연구에 더욱 엄격한 데이터 정합성 검증 절차를 적용하게 되었다. 교차모델 파이프라인이 정상 궤도로 복귀함에 따라, 연구팀은 이후 Phase에서 누수가 아닌 실질적 모델 향상*을 모색하는 과제들에 집중하기로 하였다.
