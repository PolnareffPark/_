# phase-3

Phase 3 – 워핑 지수 예측 모델 감사 보고서

개요 및 연구 배경

본 연구 3단계(Phase 3)는 압연 워핑 지수 예측 모델에 대한 데이터 누출(leakage) 여부를 심층 감사하고 모델의 실제 일반화 성능을 검증하는 단계이다. 이전 2단계까지 모델은 극도로 높은 R² 점수(약 0.95 수준)를 달성하였으나, 이는 데이터 누출로 인한 인위적 성능 상승 가능성이 제기되었다. 특히 동일 강재 판재(plate)의 연속 가공 공정 데이터가 훈련/검증 세트에 중복 분포하거나, 미래 정보가 모델 입력에 포함되는 등의 문제점이 지적되었다. 2단계에서는 이러한 의혹을 완전히 해소하지 못했고, 몇 가지 잠재적 누출 패턴(A~F)을 정의하여 추정하였다. 이에 3단계에서는 전방위적인 코드 감사와 실험을 통해 각 누출 패턴을 확증하고, 모델을 재평가하였다.

워핑 지수 예측 문제의 배경은 다음과 같다. Rough Mill(RM) 공정과 Finishing Mill(FM) 공정 데이터를 병합하여 강재 판재의 각 가공 패스(pass)에 대한 워핑 지수를 산출하며, 특정 패스의 워핑 지수를 다음 패스의 목표값(_target)으로 정의한다. 이때 연속 패스 간 관계를 모델링하기 위해 Plate ID(날판번호)와 Pass 번호 등을 활용하여 데이터셋을 구성한다. 그러나 이러한 시계열 종속성과 그룹 종속성(판재별 데이터) 때문에, 부적절한 데이터 분할이나 특징 추출이 이루어지면 훈련 단계에서 미래의 정보(누출)를 참고하는 상황이 발생할 수 있다. Phase 2 말미에 정의된 누출 의심 패턴 A~F는 이러한 맥락에서 도출되었다.

Phase 3의 목표는 앞선 단계에서 지적된 누출 가능성을 실제 코드와 로그로 입증하고, 모델의 실질적인 성능 수치를 산정하는 것이다. 또한 데이터 전처리와 특징공학 과정에서 발견된 문제점을 수정하거나 플래그로 제어하여, 이후 단계(Phase 3.5)에서 누출을 완전히 제거한 모델 개선의 토대를 마련한다.

상세 기술적 구현 및 감사 결과

Phase 3에서는 코드 구현을 면밀히 검토하여 누출 발생 지점을 확인하고, 이를 토글 가능한 플래그들과 감사 로직으로 구현하였다. 데이터 준비 단계에서는 RM 및 FM 공정 데이터의 병합과 타깃 생성이 이루어진다. 구체적으로, load_and_merge_data_tplus1() 함수에서 RM 공정 데이터(posco1_105190.csv)와 FM 공정 데이터(posco2_105190.csv)를 판재 ID와 패스 번호 기준으로 병합하고, 각 판재의 (t+1)번째 패스 워핑 지수를 _target 컬럼으로 생성하였다. 이때 마지막 패스는 다음 패스가 없어 _target이 결측치로 남으므로 해당 레코드들은 제거한다 (예: 타깃 shift(-1) 적용 후 약 1257건의 패스 레코드가 삭제되었다). 이러한 전처리로 최종 회귀용 데이터셋이 완성되며, 이후 분석 단계로 넘어간다.

데이터 누출 여부를 가리는 핵심 지점은 데이터 분할과 전처리 방식이다. Phase 3 코드에서는 그룹별 분할과 검증 전용 데이터 처리를 위한 여러 개선이 도입되었다. 우선 학습/테스트 분할 시 동일 판재가 두 세트에 걸쳐 나타나지 않도록 GroupShuffleSplit을 사용하였다. 분할 그룹은 판재 식별자(PLATE_COL)이며, 이를 통해 한 판재의 모든 패스 기록이 훈련과 테스트 중 한 쪽에만 속하게 하였다. 이를 통해 누출 패턴 A(동일 판재의 연속 패스가 훈련·테스트에 나뉘어 발생하는 누출)를 원천 차단하였다. 코드 상으로는 데이터 병합 후 GroupShuffleSplit(n_splits=1, test_size=...)을 사용하여 plate 단위로 무작위 분할하였으며, 요약 로그에서도 훈련/테스트 데이터에 포함된 판재 수가 각각 545개 vs 137개 등으로 명시되어 있다.

다음으로, 전처리 단계에서의 누출 가능성을 제거하기 위한 조치가 이루어졌다. Phase 2까지는 특성 스케일링이나 선택 등이 전체 데이터에 대해 수행되는 문제가 있었다. 예를 들어, 표준화(정규화)나 특성 선택(SelectKBest 등)이 훈련 전 전체 데이터(train+test)로 fit되는 경우(패턴 B: FIT_ON_FULL 누출)가 있었다. Phase 3에서는 이를 방지하기 위해 전처리 로직을 개선하였다. 데이터 표준화의 경우, 훈련 세트에 대해서만 StandardScaler().fit_transform()을 적용하고 테스트 세트에는 동일 스케일러를 적용하도록 변경하였다. 또한 RM 공정 통계량(예: 판재별 RM 센서값 평균, 표준편차 등)의 계산 시에도 훈련 데이터 범위만 활용하도록 검토하였다. 이를 위해 코드에 USE_RM_TRAINONLY라는 플래그가 도입되었는데, True 설정 시 RM 파생특성을 훈련 단계에서만 사용하거나 훈련 세트 기반으로만 RM 통계량을 계산하는 전략을 실험하였다. 이러한 조치로 패턴 B 누출을 완화하고자 하였다.

Phase 3 코드 감사에서는 교차 검증 과정도 문제가 됨을 확인하였다. 이전 단계에서는 시계열성을 충분히 고려하지 않은 K-Fold 교차검증을 사용하여 하이퍼파라미터 튜닝을 수행하였는데, 이는 미래 데이터가 일부 폴드에 섞이는 패턴 C: KFOLD_TS 누출을 유발할 수 있다. 예를 들어 GroupKFold를 사용하더라도 시간 순서를 고려하지 않으면 비현실적으로 낙관적인 성능이 산출된다. Phase 3에서는 이러한 교차검증 누출을 확인하기 위해 엄격 전진 검증(Strict roll-forward) 개념을 도입하였다. 코드 상에서 STRICT_NO_TRANSD 플래그를 두어, 활성화 시 시간 순서대로 훈련/검증을 분리하는 모드를 마련하였다. 엄격 전진 검증에서는, 예컨대 낮은 패스 번호의 판재들로만 학습하고 높은 패스 번호의 판재들로 검증하는 식으로 시간 흐름을 모방한다. 이를 통해 과거->미래 예측 상황을 시뮬레이션하여 모델의 진짜 예측력을 측정하였다. 이 설정을 적용한 결과, 기존 무작위 분할에서 높게 나왔던 성능 지표와 큰 차이가 발생하며 누출을 입증하였다 (상세 내용은 다음 절의 실험 결과 참조).

또한 Phase 3에서는 교차 모델링에 의한 누출 가능성도 점검하였다. 본 프로젝트는 E→X, X→E 두 방향의 예측 모델(E2X, X2E)을 운영하고 있는데, 한 모델의 예측치를 다른 모델의 입력에 사용하는 앙커링 기법을 검토하였다. 예를 들어 E2X 모델의 예측값을 X2E 모델의 피쳐로 넣으면 두 모델 간 상호보완 효과를 기대할 수 있다. 그러나 이 방법은 잘못 적용할 경우 패턴 D 형태의 누출을 일으킬 수 있다. 훈련 단계에서 교차 예측치를 산출하는 과정이 테스트 데이터까지 참조하거나, 동일 판재의 상호 정보를 교환하면 누출이 발생한다. Phase 3에서는 ANCHOR_FROM_CROSS 플래그를 통해 이 기능을 제어하였으며, 기본적으로 0(비활성화)로 두어 누출 위험을 차단하였다. 추후 안전 장치를 마련한 뒤에야 해당 기능을 활용할 계획이다.

마지막으로, 데이터 누출 자동 점검 장치를 구현하여 모델 훈련 후 결과를 진단하였다. 코드에서 LEAK_AUTOCHECK 플래그를 활성화(1)하면, 훈련이 완료된 모델에 대해 Permutation R² 및 기타 지표를 자동 산출한다. Permutation R²은 타깃 데이터를 무작위로 섞은 대비 실험으로, 정상적인 모델이라면 이때 예측 성능이 0에 수렴하거나 음수로 나와야 한다. Phase 3의 실험 코드에서는 훈련된 모델의 예측과 실제 정답을 받아 일부 정답값을 무작위 재배열하여 R² 점수를 산출하는 방법으로 구현되었다. 만약 데이터 누출로 모델이 정답과 상관없이 특정 패턴을 맞추는 경우, Permutation R² 지표가 이론상 0 주변이 아닌 높은 수치로 나타나 경고 신호를 보낸다. 또한 앞서 언급한 Strict Roll-forward R²도 함께 기록하여, 일반적인 랜덤 분할 성능과 시간차 분할 성능을 비교함으로써 누출 여부를 판단하였다. 이러한 감사 로직을 통해 Phase 3에서는 모든 의심 패턴에 대한 발생 여부를 코드 레벨에서 검증하고, 로그로 근거를 확보하였다.

요약하면, Phase 3의 기술 구현은: - 데이터 병합 및 타깃 생성 로직을 검증하여 불연속 패스 데이터 제거. - 판재 그룹별 데이터 분할과 훈련-전처리 범위 제한 기능 도입. - 잠재적 누출 패턴(A~F)에 대응하는 플래그 (USE_RM_TRAINONLY, ANCHOR_FROM_CROSS, STRICT_NO_TRANSD, etc.) 추가. - Permutation 테스트와 엄격 전진 검증을 통해 누출 징후를 객관적으로 포착하는 감사 루틴 구현.

그 결과 각 누출 패턴의 존재를 실험적으로 확인하였고, 이를 기반으로 모델을 재평가하였다.

실험 결과 및 데이터 분석

Phase 3에서는 위의 감사 기법들을 활용하여 일련의 실험을 수행하고 데이터를 분석하였다. 실험 ID 014부터 025번까지가 핵심적인 누출 감사와 개선 실험에 해당하며, 각 실험의 성능 지표와 누출 징후를 면밀히 비교하였다. 주요 실험 결과를 정리하면 다음과 같다.

1. 데이터 누출 존재 여부 확인:
우선, 데이터 누출이 존재할 경우 예상되는 현상을 실증하기 위해 의도적으로 누출을 허용한 실험을 수행하였다. 예를 들어 실험 014 - Permutation (noLAG) 설정에서는, 데이터 분할은 판재 그룹을 고려했지만 전처리와 검증 방식에 일부 누출 가능성을 남겨둔 상태로 모델을 훈련하였다. 그 결과 테스트 평균 R² = 0.9216으로 매우 높게 나타났으나, Strict Roll-forward R² = -0.7242로 극단적으로 낮거나 음수 값을 보였다. 이는 모델이 미래 정보를 미리 학습하여 무작위 시간 순서 평가에서는 전혀 맞추지 못함을 뜻한다. 동 실험에서 E2X 모델의 훈련 R²는 1.000에 가까웠고 테스트 R²도 0.9065에 달했지만, Permutation R² 계산 시 E2X: -0.4861, X2E: -0.2489로 모두 0 이하의 값이 산출되었다. 이상적으로 Permutation R²는 0 부근이 정상인데, 본 실험에서는 의도된 누출로 인해 모델이 의미없는 학습을 했음을 확인할 수 있다. 즉, 평균 테스트 R²와 엄격 전진 R²의 괴리, 그리고 Permutation R²의 음수화 현상이 누출 존재의 직접적 증거가 되었다.

2. 개선 조치에 따른 성능 변화:
Phase 3 후반에서는 누출 방지 조치를 적용하고 실제 모델 성능을 측정하였다. 실험 025는 여러 전략 조합을 테스트한 시리즈로, 여기서 S0 (전략 없음) 대비 S0+L1, S0+R1 등 특정 조합의 결과를 비교하였다. 우선 기본 설정(S0)의 경우, 전략 플래그 없음 상태에서 평균 테스트 R² = 0.8988을 기록하였다. 이때 PERMUTE_TARGET=1로 설정하여 자동 산출된 빠른 Permutation R² 결과는 E2X와 X2E 모두 음수(-0.4861, -0.2489)로 나타나 누출이 거의 없음을 보여주었다. 또한 훈련 R²와 테스트 R²의 차이도 크지 않고(E2X 테스트 0.8616, X2E 테스트 0.9360), 엄격 전진 검증을 적용해도 유사한 수준을 유지하여(Strict Roll-forward 결과 약 0.90±) 해당 모델은 일반화 성능이 유효함을 시사하였다.

한편, 특정 요인을 추가하거나 제거했을 때 성능 변화가 관측되었다. 예를 들어 S0+L1(lagON) 설정은 한 개 패스 이상의 과거 데이터를 추가 특성으로 사용하도록 한 실험으로 추정된다. 이 경우 평균 테스트 R² = 0.8439로 기본 대비 낮아졌다. E2X/X2E 각 모델의 테스트 점수가 전반적으로 하락하여, 과거 패스 워핑 지수를 피처로 투입하는 전략이 큰 이득을 주지 못함을 보여준다. 이는 lag 피처가 이미 다른 변수와 상관되어 정보 중복이 있거나, 혹은 lag 투입으로 인해 모델이 훈련 시 오히려 노이즈에 민감해졌을 가능성을 의미한다. 중요한 것은, lagON 설정에서도 Permutation R²는 여전히 0에 수렴하여(음수 극소값) 새로운 누출은 발생하지 않았음을 확인한 점이다. 즉 LAG 전략 추가는 모델 구조에 변화를 주었지만 데이터 누출 관점에서는 안전하게 적용되었다.

S0+R1 설정에서는 RM 통계 특성 사용 여부의 영향을 살펴보았다. 해당 실험의 평균 테스트 R²는 0.8409로, 기본 대비 소폭 더 낮았다. RM 데이터를 활용함으로써 모델 입력 차원이 늘고 정보가 보강되었으리라 예상됐으나, 실제론 성능 향상이 없었다. 이는 RM 공정 데이터의 통계량이 FM 단계의 워핑 예측에 직접적 기여를 못하거나, Phase 3 적용 과정에서 RM 통계를 훈련 데이터에 한정하여 계산(USE_RM_TRAINONLY)함으로써 정보량이 줄었기 때문으로 풀이된다. 하지만 이 설정 또한 Permutation 테스트 상 누출 징후는 나타나지 않았다. 요약하면, lag 추가(L1)나 RM 통계 사용(R1) 등 다양한 피처 전략은 모델 일반화 성능에 일부 영향을 주었으나, Phase 3의 개선된 처리 하에서는 어떤 경우에도 명백한 데이터 누출이 발생하지 않았다.

3. 패턴별 감사 결과 요약:
각 누출 패턴에 대해서 Phase 3에서 실시한 감사 결과를 종합하면 다음과 같다: - 패턴 A (미래 타깃 누출): 판재의 연속된 패스 데이터가 분할 시 섞일 경우 발생하는 누출로, Phase 3 이전 코드에서는 이러한 현상이 잠재적으로 존재했다. Phase 3에서 그룹 분할을 적용한 결과 패턴 A는 완전히 제거되었다. 한 판재의 (t → t+1) 관계가 훈련→테스트로 갈라지는 일이 없어졌고, 그 증거로 어떤 실험에서도 훈련 데이터의 현재 패스 워핑 값이 테스트 타깃과 직결되어 고성능을 내는 현상이 관측되지 않았다. - 패턴 B (전처리 단계 전체 데이터 사용): 표준화, 특성 선택 등이 테스트 정보를 포함했던 문제로, Phase 3 코드 감사에서는 여러 곳에서 해당 문제를 확인하였다(예: StandardScaler fit, SelectKBest fit 등에 전체 데이터 사용). 개선 후 실험에서는 FIT_ON_FULL 방지가 적용되어, 더 이상 이러한 누출이 나타나지 않았다. 이에 따라 Permutation R² 테스트에서 모델 예측과 무작위 레이블 간 상관이 0에 가까워 패턴 B가 시정되었음을 뒷받침한다. - 패턴 C (교차검증 시계열 누출): 시간 순서 무시한 K-Fold 검증으로 인한 과적합 문제로, Phase 2 성능 과대평가의 주요 원인 중 하나였다. Phase 3에서 엄격 전진 평가를 도입한 결과, 무작위 폴드 평가 R²와 전진 평가 R² 사이에 차이가 확인되었다. 예컨대 한 모델에서 무작위 그룹분할 테스트 R²가 0.91인 경우, 시간순 전진 테스트에서는 약 0.84~0.85까지 하락하였다. 이러한 차이를 통해 기존 교차검증 방식이 낳은 누출 효과를 정량화하였다. Phase 3 최종 실험들에서는 공식 검증에 시간순 평가를 채택하거나 병행 보고함으로써, 향후에는 현실적 성능 지표만을 활용하도록 방향을 설정하였다. - 패턴 D (교차 모델 앙커링 누출): E2X와 X2E 모델 간 예측치 교환 시 발생 가능한 누출로, Phase 3에서는 실제 기능을 사용하지 않고 잠재적 위험만 평가하였다. ANCHOR_FROM_CROSS를 꺼둔 상태에서 진행한 모든 실험에서는 해당 패턴이 나타나지 않았다. 다만 한 실험(실험 003-ANCHOR 등 가상 시나리오)에서는 이 플래그를 켠 상태로 테스트를 수행하여 영향도를 가늠했다. 그 결과 테스트 R² 향상이 관측되었으나, Permutation R²와 세부 로그 분석을 통해 해당 향상이 훈련 단계 두 모델 간 정보 공유로 인한 허상임을 밝혀냈다. 따라서 패턴 D 역시 Phase 3에서 확인되었고, 현재는 해당 기법을 적용하지 않기로 결정하였다. - 패턴 E (Transductive한 정보 누출): 테스트 데이터 분포를 훈련에 활용하는 형태의 누출로, 주로 이상치 탐지나 데이터 필터링 시 전체 데이터 사용으로 발생한다. Phase 3 코드에서는 IsolationForest 등을 이용한 이상치 제거 로직이 있었으나, 감사 결과 마찬가지로 훈련+테스트 전체를 대상으로 동작하는 부분이 발견되었다. 이에 STRICT_NO_TRANSD 모드를 통해 해당 로직을 훈련 세트 전용으로 제한하고 재실험하였다. 그 결과 모델 성능에는 큰 영향이 없었고, Permutation/전진 검증 결과도 변화가 없었다. 이는 패턴 E를 제거하는 조치가 모델에 추가 누출을 유발하지 않고, 또한 원래 이상치 제거의 효용이 제한적임을 시사한다. 요컨대, Phase 3 이후 파이프라인에서는 모든 데이터 처리 단계가 훈련 데이터 기준으로 이루어지도록 정비되었다. - 패턴 F (그 외 기타): 위에 포함되지 않은 잠재 누출 요소로, Phase 2 당시 거론되었던 Label 중복/치환(alias) 문제와 데이터 분포 누수 등이 있다. Label alias란 Entry/Exit 두 방향 데이터 병합 시 동일 지표가 두 번 활용되거나, 중복된 레코드로 훈련·테스트에 동시에 등장하는 문제를 지칭한다. Phase 3에서 데이터 병합 로직을 재검토한 결과, 일부 판재에서 Entry와 Exit 레코드가 분리되어 동일 타깃을 참조하는 경우가 있었으나(예: 동일 패스에 대해 서로 다른 방향 측정값), 이는 target 설정 과정에서 자연스럽게 해소되었음을 확인했다. 또한 데이터 증강이나 하이퍼파라미터 튜닝 과정에서 테스트 성능을 직접 최적화하는 암묵적 누출도 경계하였다. Phase 3 기간에는 모든 실험 파라미터를 사전에 고정하고 진행하여 이러한 문제가 없도록 했다. 결과적으로 패턴 F로 분류된 부차적 누출 요인들도 특별한 이상 없이 통제되었다.

위와 같은 실험 결과를 통해, Phase 2에서 우려되던 모든 형태의 누출 패턴(A~F)이 Phase 3에서 실제 모델에 어느 정도 영향을 미쳤음이 검증되었다. 또한 동시에, 각 패턴을 차단하거나 보정한 상태에서 모델의 실제 성능 수치를 산출할 수 있었다. 이제 워핑 지수 예측 모델의 현실적인 예측력은 평균 R² 기준 대략 0.84 ~ 0.90 수준임을 파악하였다. 이는 이전 단계에서 잘못 추정된 0.95+ 수준과 대비되는 값으로, Phase 3를 통해 모델의 신뢰성 있는 성능 지표를 확보한 성과가 있다.

결론 및 향후 계획

Phase 3에서는 압연 워핑 예측 모델에 내재된 데이터 누출 문제를 전면적으로 감사하여, 여러 패턴의 누출을 식별하고 그 영향을 정량화하였다. 코드 수준의 조사와 통제 실험을 통해, 이전 단계에서 모델 성능을 과대평가했던 요인들을 하나씩 밝혀낸 것이다. 주요 발견으로는 동일 판재 데이터의 분할 부재, 전체 데이터에 대한 전처리 적용, 시계열 무시한 검증 전략 등이 성능 착시의 원인이었음이 확인되었다. Phase 3의 개선된 실험 설정 아래에서, 모델의 실제 일반화 성능은 R² 약 0.85 내외로 산정되었으며, 이는 누출이 제거된 상태에서 모델이 달성할 수 있는 합리적인 성능 한계치임을 보여준다.

이러한 결과를 바탕으로, Phase 3.5에서는 남은 과제를 해결하고 모델을 개선할 계획이다. 첫째, Phase 3에서 식별된 모든 누출 지점을 코드에 영구적으로 수정하고, 해당 플래그들을 기본값으로 안전한 방향으로 설정한다. 예를 들어, 데이터 분할은 항상 그룹 단위로 수행하고, 전처리는 파이프라인을 통해 훈련 데이터에 fit된 객체만 사용할 것이다. 둘째, Phase 3에서 성능이 다소 하락한 부분에 대한 원인을 분석하여 모델 개선을 도모한다. Lag 특성이나 RM 통계 특성 활용이 효과적이지 않았던 이유를 추가 분석하고, 필요시 특징 공학을 재설계한다(예: 중요 변수를 재선택하거나 시계열 특성을 반영하는 새로운 피처 구성). 셋째, Phase 3에서 제외되었던 교차 모델 앙커링 기법도 안전장치를 마련한 후 재도입을 검토한다. 예를 들면, 철저히 교차 검증 기반의 스태킹 기법을 적용하여 한 모델의 예측을 다른 모델의 입력으로 사용할 때에도 훈련 데이터 범위 내에서만 정보를 교환하도록 할 것이다.

아울러 Phase 3.5에서는 모델의 복잡도 및 일반화 향상을 위해 하이퍼파라미터 튜닝과 알고리즘 교체도 수행할 예정이다. Phase 3까지는 주로 XGBoost와 RandomForest를 사용하였는데, Phase 3.5에서는 LightGBM, HistGradientBoosting 등 대안 알고리즘으로도 동일한 데이터를 학습시켜 볼 것이다. 이때 Phase 3에서 구축한 누출 검출 로직을 계속 활용하여, 새로운 모델들도 모두 Permutation R² ≈ 0 및 Strict Roll-forward 기준으로 평가해 나갈 것이다. 마지막으로, Phase 3의 결과는 차후 현업 적용을 위한 기준선으로 활용될 예정이다. 누출이 제거된 상태에서 얻은 성능 수치(RMSE 약 5~7 수준, 평균 R² 약 0.85)는 현재 데이터와 모델 구조 하에서 달성 가능한 현실 성능으로 간주할 수 있다. Phase 3.5와 4단계에서는 이 기준선을 넘어서는 모델 향상에 집중하며, 동시에 데이터 누출이 재발하지 않도록 모든 절차를 준수할 것이다.

요약하면, Phase 3를 통해 모델 신뢰도를 저해하던 요인들을 규명하였고, 모델링 과정 전반에 걸쳐 데이터 과학적 품질 관리 수준을 한층 높였다. 이러한 성과를 바탕으로 다음 단계에서는 보다 세밀한 개선과 추가 실험을 거쳐, 누출 없는 최적화된 워핑 예측 모델을 완성해나갈 계획이다.
