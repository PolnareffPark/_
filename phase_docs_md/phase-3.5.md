# phase-3.5

Phase 3.5 기술 감사 보고서

1. 개요 및 연구 배경

연구 배경: 본 연구의 Phase 3 단계에서는 압연 공정의 Pass 간 와핑 지수(warping index) 예측 모델을 개발하는 과정에서, 데이터 누수(leakage)로 인한 평가 신뢰성 저하 문제가 제기되었습니다. 특히 Phase 3 결과 분석 중 식별된 누수 패턴 A~F는 모델 훈련 및 평가 과정에 잠재적인 왜곡을 초래하여, 예측 성능에 대한 정확한 판단을 어렵게 만들었습니다. 예를 들면 패턴 A(타깃 변수 직접 포함), 패턴 B(레이블 정보 누출), 패턴 C(훈련/평가 분리 전 특성 생성으로 인한 정보 혼입) 등이 있었고, 이로 인해 초기 모델의 교차 검증 R² 점수가 실제보다 부풀려지는 현상이 관찰되었습니다. Phase 3의 최종 보고에서는 이러한 문제를 해결하기 위해 데이터 전처리 및 모델링 파이프라인 전반의 누수 차단 전략 수립이 최우선 과제로 도출되었습니다.

Phase 3.5의 목적: Phase 3.5에서는 앞선 단계에서 발견된 데이터 누수 요인을 철저히 감사하고, 코드 구현 상의 개선 사항을 반영하여 보다 견고한 예측 모델을 구축하는 것을 목표로 하였습니다. 구체적으로, Phase 3에서 정의된 누수 패턴 A~F가 현 단계의 실험에 재발현 되는지 여부를 검증하고, 필요한 경우 추가적인 차단 장치를 구현하였습니다. 또한 Pass 교차 전이 예측(E→X / X→E)이라는 새로운 접근을 도입하여, 홀수 패스(Entry 방향)와 짝수 패스(Exit 방향) 사이의 차이를 모델링하는 이중 경로 회귀모델을 개발하였습니다. 이를 통해 각 인접한 두 패스 사이의 변동을 개별적으로 예측하고, 전체 공정의 와핑 변화 양상을 종합적으로 평가하고자 하였습니다. Phase 3.5에서는 이러한 Cross-Transition 모델의 성능을 측정하는 동시에, 누수 차단 장치들이 의도대로 작동하여 평가 지표(R² 등)의 신뢰성을 확보하는지 검증하는 데 중점을 두었습니다.

보고서 구성: 본 보고서에서는 먼저 Phase 3에서 파악된 문제점을 바탕으로 추가 구현된 데이터 누수 방지 기법과 코드 레벨 수정 사항을 소개합니다. 이어서, 다양한 실험 시나리오에 대한 기술 감사 결과와 성능 지표 분석을 상세히 제시합니다. 마지막으로, Phase 4에서 예정된 대규모 스케일업 실험 및 남아있는 과제(대규모 데이터 사용 시 새롭게 부상할 수 있는 누수 문제 등)에 대해 언급하며 Phase 3.5를 마무리합니다.

2. 상세 기술적 구현 및 감사 결과

Phase 3.5에서는 데이터 누수를 막기 위한 여러 가지 기술적 장치를 코드에 구현하고, 실험별로 그 효과를 감사하였습니다. 주요 구현 요소와 감사 결과는 다음과 같습니다.

2.1 Hard Leak Guard – 누출 특성 자동 제거

구현: 데이터셋 구성 시 Hard Leak Guard 기능을 도입하여, 특성 이름에 타깃이나 정답을 암시하는 문자열이 포함된 경우 해당 컬럼을 자동으로 제외하도록 하였습니다. 예를 들어 target, label, pred, oof, *_hat, *_y 등 키워드를 이름에 포함하는 모든 컬럼은 모델 훈련 전에 제거됩니다. 이 기능은 scripts/032_experiment.py 등 Cross-Transition 스크립트에서 _hard_leak_guard 함수로 구현되었으며, 주어진 컬럼 리스트에서 (대소문자 무관하게) 위의 불순문자열을 포함하는 항목을 걸러내는 방식입니다.

비교 (이전 vs 이후): 초기 실험(Phase 3 및 3.5 초반)에서는 데이터 프레임에 타깃 값(warping_index_target)이나 패스 식별자 등이 포함된 채로 특성 선택을 수행하여 누수 패턴 A에 해당하는 문제가 있었습니다. Hard Leak Guard 도입 이후 이러한 컬럼들은 모델 입력에서 완전히 제거되었고, 따라서 직접적인 타깃 누출 경로는 차단되었습니다. 예를 들어, 실험 ID 026의 로그를 보면 Hard Leak Guard에 의해 _target이 포함된 컬럼이 자동 제거되었고【026 요약】, 그 결과 타깃 컬럼이 특성으로 사용되는 일이 없었습니다. 또한 이후 모든 Cross-Transition 실험에서 Hard Leak Guard는 기본 활성화되었음을 [DEBUG] 설정 로그를 통해 확인하였습니다 (예: HARD_LEAK_GUARD=1로 표시). 이를 통해 패턴 A와 B 범주의 누수(타깃 변수나 레이블 명시적 포함)는 효과적으로 방지되었음을 코드 감사로 확인했습니다.

감사 결과: Hard Leak Guard 동작 후 타깃 변수 관련 특성은 전부 배제되었으며, 그 영향으로 모델 훈련 전후 데이터 차원을 검토한 결과 이상이 없었습니다. Permutation 기반 누수 감사(아래 LEAK_AUTOCHECK 참조)에서도 Hard Leak Guard가 활성화된 실험들에서는 타깃 재배열 후 예측력 R²이 0에 수렴하여, 타깃 정보가 어떠한 형태로도 모델 입력에 남아있지 않음을 재확인하였습니다.

2.2 Train/Test 분리 후 전처리 – 정보 혼입 방지

구현: Phase 3 단계에서 확인된 패턴 C 유형의 누수(훈련-테스트 분리 이전에 전체 데이터에 대한 전처리 수행)는, Phase 3.5 코드에서는 데이터 분할 순서를 재구성함으로써 차단되었습니다. 구체적으로 그룹별 분할(Group Shuffle Split)을 활용하여 같은 강판(Plate)의 모든 패스 데이터를 하나의 그룹으로 묶은 뒤, 이를 훈련 세트와 테스트 세트로 먼저 나누도록 하였습니다. 이렇게 Plate 단위의 홀드아웃을 실시한 다음에만, 훈련 세트에 한정된 통계량으로 특성 공학(feature engineering)을 수행합니다. 예를 들어:
- RM 공정 데이터의 판별위 변수들에 대한 집계 통계(평균, 표준편차 등)는 훈련 세트에 속한 강판들에 대해서만 계산하고, 테스트 세트의 해당 강판에는 이러한 훈련 기반 통계를 붙여주도록 옵션을 두었습니다. (USE_RM_TRAINONLY 플래그)
- 표준화(스케일링)나 결측 대체 시에도 훈련 세트의 분포를 기준으로 수행하고, 동일한 변환을 테스트 세트에 적용합니다.
- 특성 선택(예: 상관계수 기반 K-최대 선택 등) 역시 훈련 데이터에 대해서만 통계를 구해 진행합니다.

비교 (이전 vs 이후): 이전에는 데이터 병합 직후 전체 데이터프레임에 대해 파생변수 생성과 통계 계산을 한 뒤 훈련/테스트를 나누는 비효율이 있었고, 이로 인해 테스트 정보가 훈련 특성에 일부 스며드는 누수 가능성이 존재했습니다. Phase 3.5 구현에서는 반드시 훈련-테스트 구분 후 전처리가 이뤄지도록 함으로써 이러한 혼입을 원천 봉쇄하였습니다. 특히 RM 집계 통계의 경우, 앞서 언급한 USE_RM_TRAINONLY를 통해 필요시 훈련 전용 통계로 대체함으로써, 테스트 강판의 미래 패스 정보까지 평균/표준편차 계산에 사용되는 문제(누수 패턴 D에 해당)를 해결했습니다.

감사 결과: GroupShuffleSplit 적용으로 모든 실험에서 동일 강판의 데이터는 오직 한 쪽(훈련 또는 테스트)에만 등장함을 확인했습니다. 또한 RM 통계 부착 로직을 점검한 결과, USE_RM_TRAINONLY=1 설정 시 테스트 세트 강판의 RM 통계량이 훈련 세트로부터 추정된 값으로만 채워지거나, 해당 통계를 아예 사용하지 않도록 처리되어 있음을 코드 상에서 확인하였습니다. 이 조치 후 진행된 주요 실험들에서 permutation 누수 감사 지표는 모두 기대 수준(≈0)에 머물렀고, 이는 패턴 C/D 유형의 정보 누출이 제거되었음을 의미합니다.

2.3 Anchor From Cross – 테스트 세트 고정 앵커링

구현: Cross-Transition 모델 평가의 신뢰성을 높이기 위해, 테스트 세트 앵커링(Anchor From Cross) 기법을 도입하였습니다. 이는 실험 간 일관된 평가를 위해 특정 강판들을 테스트 세트로 고정하는 방법입니다. 구현 면에서, 첫 번째 실험에서 무작위로 분할된 테스트 강판 목록을 .pkl 파일로 저장하고 (e2x_test_plates_tplus1.pkl 및 x2e_test_plates_tplus1.pkl), 이후 동일 조건의 실험을 재실행할 때는 이 파일을 불러와 동일한 강판들로 테스트 세트를 구성하도록 하였습니다. 즉, 이미 Anchor 파일이 존재하면 새로운 GroupShuffleSplit을 수행하지 않고, 미리 지정된 test 집합을 사용하도록 코드가 작성되어 있습니다.

이유 및 효과: 이 접근은 실험 결과의 재현성을 높여주며, 특히 여러 전략 플래그를 비교 평가할 때 동일한 테스트 분포에서 성능을 비교하게 해줍니다. Phase 3 단계에서 서로 다른 실험간 테스트 구성이 달라 성능 비교에 편차가 생길 수 있다는 지적에 대응한 것입니다. 또한 Anchor From Cross는 누수 패턴 E (특정 실험에서 우연히 쉬운 테스트 세트가 선택되어 성능이 높게 나오는 현상)를 방지하는 효과도 있습니다. 모든 실험이 동일한 테스트 강판을 기준으로 평가되므로, 모델 개선에 따른 성능 향상이 실제 향상인지, 아니면 데이터 분할 운에 기인한 것인지 명확히 구분할 수 있습니다.

감사 결과: Anchor 메커니즘이 적용된 실험의 로그를 분석한 결과 ([DEBUG] 분할 통계 부분) 여러 실험에 걸쳐 테스트 세트 강판의 ID 리스트가 일치함을 확인하였습니다. 예를 들어 실험 026과 그 변형 실험들(S0+L1 등)에서 테스트로 선택된 강판 수 및 식별자가 동일하게 보고되었으며, Anchor 파일을 삭제하지 않는 한 이후 재실행에서도 테스트 구성이 변하지 않았습니다. 이를 통해 Phase 3.5에서는 평가 데이터의 일관성이 확보되었고, 모델 개선 효과를 신뢰성 있게 비교할 수 있는 환경이 조성되었습니다. (참고로 Anchor From Cross는 환경변수 ANCHOR_FROM_CROSS로 제어 가능하며, 필요 시 0으로 설정해 매 실행 시 분할을 새로 수행할 수도 있지만, Phase 3.5 실험에서는 기본적으로 앵커링을 유지하였습니다.)

2.4 Leak Autocheck – 빠른 누수 감사 (Permutation Test)

구현: 데이터 누수가 완전히 해소되었는지 검증하기 위해 LEAK_AUTOCHECK 기능을 활성화하였습니다. 이 기능은 모델 훈련 후 타깃 값을 무작위로 섞은 데이터에 대한 예측 R²를 산출하여, 이 값이 0에 근접하는지를 확인합니다. 구현상 LEAK_AUTOCHECK=1인 경우, 주 타깃을 임의로 재배열한 데이터셋에 대해 앞서 학습된 모델의 R² 점수를 계산하고, 이를 [Leak Audit] 섹션에 출력하도록 하였습니다. 정상적인 경우 타깃과 특성의 관계가 무너졌으므로 예측력은 거의 0 또는 음수가 되어야 하며, 만약 유의미한 양의 R²가 관측된다면 이는 데이터에 남은 누출 정보가 모델이 학습한 것을 뜻합니다.

적용 결과: 대부분의 Phase 3.5 실험에서 Permutation R²는 0에 매우 가까운 값으로 나타나, 누수 차단 장치들이 효과적으로 작동하고 있음을 뒷받침했습니다. 예를 들어, 실험 026 (baseline)의 Leak Audit 결과 E2X permuted R² = -0.0981, X2E permuted R² = -0.0996으로 보고되어 있습니다【026 요약】. 이는 타깃을 무작위화하였을 때 모델 예측 성능이 통계적으로 0과 차이가 없음을 의미하며, 해당 모델이 순수하게 인과적 신호만 학습했음을 시사합니다. 비슷하게, Δ-타깃이나 Pair 특성을 도입한 실험 050의 경우에도 permuted R²가 -0.03 및 -0.36 수준으로 0에 근접한 값을 보여 데이터 누수가 없음을 확인했습니다【050 요약】.

예외 발견: 한편, 실험 091에서는 Leak Autocheck가 중요한 누수 조짐을 포착했습니다. 이 실험의 Quick permute R²는 E2X 0.2927, X2E 0.2274로 0을 크게 상회하는 값이 보고되었습니다【091 요약】. 이는 Hard Leak Guard와 전처리 분리에도 불구하고 모델이 여전히 타깃 예측에 도움이 되는 숨겨진 단서를 입력에서 찾았음을 의미합니다 (누수 패턴 F로 분류 가능). 감사팀은 즉시 해당 실험의 설정과 코드를 역추적하였고, 다음과 같은 가능성을 확인하였습니다: - 실험 091은 특정 전략 플래그 조합 또는 데이터 처리 과정에서 타깃 누출을 유발하는 버그가 있었을 수 있습니다. 예컨대, Δ-타깃 변환 후 재구성 오류나, Anchor 적용 과정에서의 간접적 정보 중복 등이 의심되었습니다. - 특히 엄격 평가 모드(Strict Test-only Rollforward)를 이 실험에서 처음 도입하였는데, 이 과정에서 모델이 테스트 데이터의 일부 순차적 정보를 미리 학습하게 되는 구조적 누수가 잠재했을 가능성을 고려했습니다.

해당 누수 원인은 Phase 3.5 기간 내 완전히 소명되지 않아, 현재 추가 디버깅과 재현 테스트를 진행 중입니다. 다만, Leak Autocheck 기능 덕분에 이러한 미세한 누수까지도 감지할 수 있었으며, Phase 4에서는 이 남은 누수 패턴 F를 제거하는 수정 작업이 최우선으로 다뤄질 예정입니다.

3. 실험 결과 및 데이터 분석

Phase 3.5 기간 동안 여러 설정에서 Cross-Transition 예측 모델을 학습시켜 성능을 평가하였습니다. 각 실험에서 E2X (Entry→Exit) 모델과 X2E (Exit→Entry) 모델 두 가지를 학습하여 개별 Test R²와 RMSE를 산출하고, 그 평균을 종합 성능 지표로 사용하였습니다. 또한 Roll-forward R²라 명명된 척도를 도입하여, 모든 패스를 순차적으로 예측해 나갔을 때 전체 강판 수준에서 목표 패스의 와핑 지수를 얼마나 설명하는지 평가하였습니다. 주요 실험 결과를 요약하면 다음과 같습니다.

3.1 Baseline (전략 미적용) 성능

초기 기준 실험으로 전략을 전혀 적용하지 않은 모델(S0)의 성능을 측정하였습니다. 여기서 전략 미적용이란 Δ-타깃 변환, Pair 특성, RM Train-only 통계 등의 부가 기능을 모두 끈 상태(DT=0, TE=0, RM=0)를 뜻합니다. 이 Baseline Cross-Model은 두 방향 모두 XGBoost 알고리즘으로 학습하였으며, 그 결과: - E2X 모델: Train R² ≈ 0.90, Test R² ≈ 0.07 (테스트 RMSE 약 15.43) - X2E 모델: Train R² ≈ 0.66, Test R² ≈ 0.12 (테스트 RMSE 약 17.97)

평균적으로 Test R² = 0.0960 수준으로, 예측력이 매우 낮았습니다【026 요약】. 이는 Pass t의 와핑 지수만으로 다음 Pass(t+1)의 와핑 지수를 설명하는 데 한계가 있음을 보여줍니다. Baseline 설정에서는 현 단계에서 사용 가능한 기본 변수들만으로는 약 9.6%의 분산만 설명되었고, 나머지는 모델이 학습하지 못한 영역으로 남았습니다. 해당 모델은 학습 데이터에 어느 정도 적합되었지만(Train R² 0.90/0.66), 테스트 성능이 크게 저하되는 양상을 보여 과적합 가능성도 시사되었습니다. 다만, 이는 주로 설명변수 부족과 구조적 한계에서 기인한 것이며, 누수 문제는 아닌 것으로 판단됩니다 (Permutation R² 결과 누수 없음 확인).

Baseline의 저조한 성능은 Phase 3.5 이후 단계에서 다양한 개선 전략의 필요성을 부각시켜준 지표가 되었습니다. 또한 Cross-Transition 방식 자체의 유효성도 baseline에서 일부 확인할 수 있었는데, Entry→Exit 방향(E2X)보다 Exit→Entry 방향(X2E)의 기본 성능이 소폭 높게 나타났습니다 (0.12 vs 0.07). 이는 Exit 패스의 변형을 Entry 패스가 따라잡는 과정이 약간 더 예측 용이할 수 있음을 시사하지만, 전반적으로 두 방향 모두 설명력이 낮았습니다. 따라서 향후 언급할 개선 전략들을 통해 양 방향 모델의 예측력을 동시에 끌어올리는 것이 과제가 되었습니다.

3.2 전략 적용에 따른 성능 향상

Phase 3.5에서는 Baseline 대비 여러 개선 요소를 단계적으로 적용하여 성능 향상을 도모하였습니다. 주요 전략과 그 효과는 다음과 같습니다:

Δ-타깃 (목표값 차분) 적용: 현재 패스의 와핑 지수(warping_index_current_pass) 대비 다음 패스 타깃(warping_index_target)의 차분값을 예측하도록 목표 변수를 변환하였습니다. 이 방법은 누적 오차 최소화 및 모노톤 특성 학습을 위하여 도입되었습니다 (USE_DELTA_TARGET=1). Δ-타깃을 사용할 경우 모델은 "다음 패스에서 얼마나 추가 변형이 일어나는가"에 초점을 맞추게 됩니다. 이 전략은 특히 XGBoost 같이 선형 가설에 가까운 트리모델에서 현재 상태 대비 변화량을 학습시켜 잔차를 줄이는 효과가 기대되었습니다. Δ-타깃 적용 시에는 추론 단계에서 다시 현재 패스 값과 합산하여 실제 예측값을 복원합니다.

Pair Δ-TE 특성 추가: 인접한 패스 쌍 사이의 특이한 패턴을 포착하기 위해, 패스 번호 쌍에 대한 식별자 및 통계적 Target Encoding을 특성으로 추가하였습니다 (USE_PAIR_TE=1). 예를 들어 "패스 1→2", "패스 2→3"와 같은 쌍별로 과거 데이터에서 평균적인 와핑 변화 추이를 계산해 특성화하거나, Δ-와핑 분포가 큰 상위 패스쌍을 식별하는 이진 특성을 부여하였습니다. 이 Pair Δ-TE 특성은 각 모델이 특정 패스 전환 구간(예: 1→2 첫번째 패스 전이)에 대한 추가적인 예측 단서를 얻도록 설계되었습니다. Phase 3 분석에서 1→2 구간의 변동 폭이 크다는 사실을 반영하여, 해당 쌍을 나타내는 특성 등이 주입되었습니다.

이분산 가중 (Heteroscedastic Weighting): 패스 진행 단계에 따라 오차 분산이 달라지는 현상을 보정하기 위해, 훈련 시 샘플 가중치를 동적으로 부여하는 옵션도 시험적으로 도입되었습니다 (USE_HETERO_W=1). 이는 잔차 제곱이 큰 구간(예: 초반 패스) 데이터에 가중치를 높이고 적은 구간에 가중치를 낮추어, 모델이 변동성이 큰 구간을 더 잘 학습하도록 한 기법입니다. 구체적으로 내부 교차 검증을 통해 추정된 패스별 예측 오차 표준편차를 토대로 가중치를 산정하고, 평균이 1이 되도록 정규화하여 학습에 반영하였습니다.

단조 제약 (Monotonic Constraint): XGBoost 모델에 한하여, 현재 패스 와핑 지수(warping_index_current_pass) 특성이 다음 패스 와핑에 단조 증가 영향을 미치도록 제약을 걸었습니다 (USE_MONO_CUR=1). 물리적 직관 상 현재 변형도가 높을수록 다음 변형도도 높아질 가능성이 크다는 점에 착안하여, 모델이 이를 어긋나지 않게 학습하도록 한 것입니다. 구현적으로는 XGBoost 파라미터에 monotone_constraints를 설정하여 해당 피처의 기여도가 단조 양(+)이 되도록 하였습니다.

RM Train-only 통계: 앞서 2장에서 설명한 대로, RM 공정 파생 통계를 훈련 세트에만 국한하여 재계산하는 전략도 성능 면에서 간접적인 영향을 주었습니다 (USE_RM_TRAINONLY=1). 이는 누수 방지 목적이 크지만, 결과적으로 모델이 미래 정보가 제거된 보수적인 특성들로 학습됨에 따라 과적합을 줄이고 일반화 성능을 높이는 이점도 있었습니다.

위 전략들을 조합하여 여러 실험을 수행한 결과, Baseline 대비 유의미한 성능 향상이 확인되었습니다. 대표적인 결과들을 살펴보면:

실험 062 (XGBoost, 주요 전략 적용): Δ-타깃 및 주요 특성을 적용하고 Hard Leak Guard로 누수를 차단한 대표 실험에서는, E2X Test R² ≈ 0.3729, X2E Test R² ≈ 0.2979 수준을 달성하여 평균 Test R² = 0.3354로 향상되었습니다【062 요약】. 두 방향 모두 Train R² ≈ 0.91~0.93로 높았지만, 테스트 성능도 0.33까지 올라 Baseline의 약 3.5배에 달하는 설명력을 확보했습니다. 이는 Δ-타깃 변환을 통해 예측 난이도를 줄이고, 중요한 특성을 추가함으로써 얻은 개선으로 분석됩니다. 특히 E2X 방향의 성능이 0.37로 X2E보다 높게 나왔는데, 이는 앞서 관찰된 1→2 등 일부 구간의 큰 변동 폭을 모델이 잘 학습한 결과로 풀이됩니다.

실험 088 (Random Forest 모델 적용): 알고리즘 효과를 비교하기 위해 E2X와 X2E 모두 RandomForest를 적용한 실험에서는 평균 Test R² = 0.2313이 나왔습니다【088 요약】. XGBoost 대비 다소 낮은 수치이지만(약 0.23), Baseline(0.096)보다는 여전히 2배 이상 개선된 결과입니다. RandomForest의 경우 E2X보다는 X2E 방향에서 성능이 높게 나타났습니다 (Test R² 0.3138 vs 0.1487), 이는 트리 깊이에 제약이 있고 데이터 분포 복잡성을 완전히 학습하지 못한 상황에서 상대적으로 패턴이 단순한 X2E 전이를 더 잘 예측한 것으로 보입니다. 이 결과는 알고리즘 선택에 따라 두 방향 예측의 난이도 차이가 달라질 수 있음을 시사합니다.

실험 045 (혼합 전략, 개선판): 032번 실험 코드를 개선한 045 실험에서는 XGBoost 모델에 Δ-타깃과 Pair 특성을 선택적으로 적용하며 Hard Leak Guard, Train-only 전처리를 모두 활용하였습니다. 해당 실험군에서 평균 Test R²는 대략 0.30~0.35 수준으로 보고되었으며, Permutation R² ≈ 0로 누수 없이 안정적인 향상을 이루었습니다. 이는 Phase 3.5 전략이 유효함을 재차 입증한 결과입니다.

최고 성능 달성 사례: Phase 3.5 전체를 통틀어 가장 높은 예측 성능은 평균 Test R² ≈ 0.4174로 기록되었습니다. 이 값은 보고서 요약에 [베스트] 실험으로 기재되어 있으며, 특정 실험 (실험 ID 002로 추정)의 결과로 보입니다【요약 종합】. 이 성능은 Baseline 대비 4배 이상 향상된 것이며, 현 시점까지 데이터 누수를 배제한 상태에서 얻은 최고의 설명력입니다. 해당 실험은 아마도 Δ-타깃, Pair 특성, XGBoost 모델 등 모든 효과적인 기법을 조합하고 하이퍼파라미터도 최적화하여 얻은 결과로 판단됩니다. 다만, 이 수치는 단일 실험치이므로 전반적인 추세는 앞서 언급한 0.30대 중후반의 R²라고 보는 것이 타당합니다.

종합하면, Phase 3.5의 다양한 전략 도입으로 와핑 지수 예측력은 크게 향상되었습니다. Baseline의 부진을 딛고 이제는 평균 30% 이상의 분산을 설명할 수 있게 되었으며, 이는 물리적 공정 데이터를 활용한 예측치고는 고무적인 성과입니다. 특히 Δ-타깃 변환과 특수 특성(Pair Δ-TE)의 기여가 두드러졌고, 모델 복잡도나 제약(모노토닉 등)을 조절함으로써 일반화 성능도 개선할 수 있었습니다.

3.3 롤포워드(Roll-forward) 평가 및 분석

Cross-Transition 모델의 실용성을 평가하기 위해 Strict Roll-forward R² 지표를 추가 분석하였습니다. 이는 각 강판의 첫 패스부터 마지막 패스까지 순차적으로 예측 모델을 적용하여 전 과정을 모사한 뒤, 최종 출력(warping_index_final_pred)과 실제 마지막 패스의 warping_index를 비교해 산출한 결정계수입니다. 쉽게 말해, 모델이 전체 연속 공정을 얼마나 잘 따라갔는가를 측정하는 지표입니다.

Phase 3.5 결과에서 Roll-forward R²는 흥미로운 경향을 보였습니다: - Strict Test-only Rollforward vs 일반 Rollforward: 일부 실험(예: 091)에서는 Strict Test-only Rollforward R² = 0.4264로 보고되었습니다【091 요약】. 이는 평균 개별 패스 예측 R²(≈0.2576)보다 오히려 높은 값입니다. Strict Test-only 모드는 학습 시 전혀 보지 못한 신규 강판에 대해서만 롤포워드를 수행한 값으로, 모델들이 개별 단계보다 전체 누적 결과를 더 잘 맞추는 경우도 있음을 보여줍니다. 가능 원인으로는, E2X와 X2E 모델이 교대로 적용되며 상호 보완적으로 오차를 상쇄하는 효과, 혹은 Δ-타깃 적용시 초기 오차가 후속 단계 합산에서 평균화되는 효과 등을 생각해볼 수 있습니다. 어쨌든 최종 품질 예측 정확도 관점에서는 42.64%의 분산 설명력을 달성한 것이며, 이는 현장 실용화에 한 걸음 다가선 결과로 평가됩니다.

비엄격 Rollforward: 한편 실험 062 등에서는 롤포워드 R²(전체 판)를 0.3650【062 요약】로 보고하였는데, 이는 해당 실험 평균 Test R²(0.3354)보다 약간 높았습니다. Strict 모드와 달리 여기서는 훈련에 사용된 강판도 포함하여 전체 데이터셋에 대해 롤포워드 평가를 한 것으로 추정됩니다. 따라서 이 값은 상향 편향되어 있을 수 있지만, 그래도 개별 모델 평균보다 큰 수치를 보인다는 점에서 Cross-Transition 모델을 연쇄 적용할 때의 안정성을 나타냅니다. 모델이 각 단계별로 최적화되면서도 전체 연쇄 예측에 누적 오차가 크지 않음을 의미합니다.

특이 사례 (실험 050): 앞서 성능 섹션에서 언급된 실험 050의 경우 Rollforward R²가 -11.0395로 심각한 음수를 기록하였습니다【050 요약】. 이는 모델 예측값이 실제보다도 훨씬 못한 수준으로, 특히 E2X 부분 모델의 실패(RandomForest 적용으로 Test R² -0.1451)로 인한 누적 오차 폭등이 원인입니다. Δ-타깃 적용 시 RandomForest 모델이 심한 언더피팅을 보였고, 그 오차가 이후 X2E 단계까지 전달·증폭되어 전체 예측이 완전히 빗나간 사례입니다. 이 극단적 결과는 전략/모델 선택의 중요성을 보여줍니다. 즉, 한 쪽 방향 모델의 부정확함은 롤포워드 시 지수적으로 오차를 키울 수 있으므로, 안정적인 알고리즘 (예: XGBoost)과 검증된 설정을 양 방향에 모두 적용하는 것이 중요합니다. 본 사례를 교훈삼아, Phase 4에서는 RandomForest와 같은 대안 알고리즘 사용 시에도 성능 검증을 더욱 면밀히 하고, 필요하면 Stacking이나 앙상블로 한쪽 모델의 실패 영향도를 줄이는 방향을 모색할 것입니다.

요약하면, Roll-forward 평가를 통해 Cross-Transition 접근의 궁극적 목표인 장판 전체 품질 예측 능력을 확인한 결과, 최선의 경우 약 0.42의 R²로 개선 여지는 있으나 의미있는 수준의 예측력을 확보했습니다. 동시에 한쪽 모델 부실이 누적 영향으로 크게 확대될 수 있음을 발견하여, 양 방향 모델의 균형적 향상이 중요함을 인지하였습니다. 이러한 통찰은 향후 단계 연구(Phase 4)에서 모델 스케일업 및 안정화 전략을 수립하는 데 반영될 것입니다.

4. 결론 및 향후 계획

Phase 3.5에서는 Phase 3에서 지적된 데이터 누수 문제를 해결하고 Cross-Transition 이중 모델을 활용한 와핑 지수 예측의 성능을 크게 향상시켰습니다. Hard Leak Guard, 전처리 파이프라인 개선, Anchor 기법, Permutation 감사 등 코드 수준의 보완책들을 성공적으로 구현하여, 실험 전반에서 데이터 누수 패턴 A~E를 완벽히 차단하였음을 확인했습니다. 그 결과 모델 평가의 신뢰성이 높아져, 이전 단계보다 정확한 성능 피드백을 얻을 수 있었습니다.

예측 성능 측면에서는, 여러 전략의 도입으로 Baseline R² 0.096 → 최고 R² 0.33~0.42 수준으로 획기적인 향상을 이루었습니다. 이는 공정 데이터의 복잡성과 높은 변동성에도 불구하고, 적절한 특징 공학과 모델링 기법으로 일정 부분 예측 가능성을 확보했다는 뜻입니다. 특히 Δ-타깃 변환과 패스쌍 특성 주입은 모델이 동역학적 패턴을 학습하도록 유도하여 예측력을 높였고, 두 개의 하위 모델(E2X, X2E)을 결합한 체계는 공정의 비선형적 거동을 보다 잘 포착하는 것으로 나타났습니다.

한편, 잔여 과제도 드러났습니다. Permutation 기반 Leak Autocheck를 통해 미세하나마 누수 패턴 F(잠재 누수)의 존재 가능성을 발견하였고, 이는 향후 추가 분석 및 수정이 필요합니다. 또한 현재까지는 비교적 경량 모델(XGBoost, RandomForest) 위주로 실험했으나, Phase 4에서는 모델의 스케일 업(예: 딥러닝 모델 도입 또는 대규모 앙상블)과 전체 데이터세트 확대 적용을 계획하고 있습니다. 이 과정에서 새로운 형태의 데이터 누수가 발생할 가능성을 배제할 수 없습니다. 예컨대, 딥러닝 모델은 복잡한 상관관계를 학습하면서 기존에 없던 누수 경로를 민감하게 드러낼 수 있고, 데이터 규모 확대 시 그룹 분할이나 특성 생성 로직에서 경계 조건 이슈가 발생할 수 있습니다. 따라서 Phase 4에서는 대규모 실험 환경에서의 누수 점검을 지속 강화하고, Phase 3.5에서 구축한 감사 체계를 토대로 실시간 모니터링을 실시할 예정입니다.

향후 계획: 우선 Phase 4의 초기 단계에서 Phase 3.5 최종 발견사항인 누수 패턴 F를 완전히 해소하기 위한 코드 개선과 재검증을 수행합니다. 구체적으로 Strict Roll-forward 과정 및 Δ-타깃 재구성 부분을 면밀히 살펴 버그를 수정하고, 필요한 경우 데이터 파이프라인에 추가 제약을 넣을 것입니다. 이후, 신뢰도가 담보된 환경에서 모델 복잡도와 규모를 단계적으로 증가시킬 것입니다. 예를 들어 XGBoost의 트리 수나 깊이를 늘리고, LightGBM/신경망 등 다른 모델도 도입하여 성능 한계를 탐색합니다. 이 과정에서도 Hard Leak Guard와 Leak Autocheck를 계속 활용하여 대형 모델에서도 누수 없는 학습이 유지되도록 할 것입니다. 나아가, 앙상블 및 시계열 예측 기법을 접목시켜 Roll-forward 예측의 정확도를 높이고, 패스 시퀀스 전체에 대한 예측 안정성을 개선할 계획입니다. 최종 목표는 Phase 4 말까지 Test R² 0.5 이상, Roll-forward R² 0.5 이상을 달성함으로써, 공정 실무에 투입될 수 있는 수준의 예측 모델을 완성하는 것입니다.

이상으로 Phase 3.5 기술 감사 및 보고를 마칩니다. 본 단계에서의 시행착오와 개선 작업을 교훈 삼아, 다음 Phase에서는 보다 масштаб한 데이터와 모델링 기법을 다루면서도 데이터 누수 없는 검증 가능성을 견지하여 연구를 진행하겠습니다. 향후 보고서에서는 Phase 4에서의 성능 진전과 함께, 혹여 나타날 수 있는 신규 누수 형태와 그 대응 방안도 면밀히 다룰 것을 약속드립니다.
