# phase 3

[Phase 3] : 데이터 무결성 검증 및 코드 리팩토링

1. 개요 및 연구 배경
Phase 2 실험에서 비정상적으로 높은 예측 성능(R² ≈ 0.95)이 관측되자, 모델 학습 과정에 데이터 누수(Data Leakage)가 존재할 가능성이 제기되었다. 이에 연구팀은 Phase 3에서 모델 성능 급등의 원인을 규명하기 위한 데이터 정합성 감사를 실시하였다. 구체적으로, 전체 파이프라인에 걸쳐 타깃 정보가 부당하게 학습에 스며든 부분이 있는지 포렌식 검증을 수행하고, 발견된 결함을 제거하기 위한 코드 구조 개편을 병행하였다. 이 단계의 궁극적 목표는 모델 검증 신뢰도 확보이며, 이를 위해 필요하면 기능 구현을 원점에서 재검토하고 코드베이스를 모듈화하여 향후 실험의 유지보수성을 높이고자 하였다.

2. 기술적 구현 및 감사 결과
 Leak Audit 모드 도입: 우선 014_experiment.py에 퍼뮤테이션 테스트(Permutation Test) 기반의 감사 모드가 도입되었다. 설정값 PERMUTE_TARGET=1로 전체 타깃을 무작위 셔플한 실험을 수행한 결과, 타깃을 섞었음에도 불구하고 평균 Test R²가 0.9216에 달하는 충격적인 수치가 확인되었다. 한편 동일 조건에서 시간 순서를 강제한 엄격 롤-포워드 평가(Strict Roll-forward)에서는 R²가 -0.72로 급락하였다. 이는 모델이 정상적인 물리 패턴을 학습한 것이 아니라, 검증 데이터의 정보*를 미리 학습한 것으로밖에 설명되지 않는 현상으로, 본격적인 데이터 누수의 증거가 되었다. 이에 따라 각 코드 구성 요소를 대상으로 대대적인 누수 원인 분석이 진행되었다.

데이터 누수 패턴 식별: 포렌식 감사 결과 파이프라인 곳곳에서 다음과 같은 누수 유형이 발견되었다.

Pattern A (Label Leak): 일부 실험 스크립트(예: scripts/020_test.py 등)에서 타깃 값을 나타내는 _target 컬럼이 피처 집합에 포함된 채 전처리 함수에 전달되는 오류가 확인되었다. 이 결함으로 모델 입력에 정답 레이블이 직접 주입되어, 모델이 자기대응적으로 타깃을 예측하는 상황이 발생했다.

Pattern B (Sequence Leak): 시계열 데이터 처리 로직에서 미래 값이 현재 학습에 유입되는 문제가 발견되었다. 예를 들어 merged_df.groupby(PLATE_COL)["warping_index"].shift(-1)와 같은 코드가 사용되어, 동일 판(Plate)의 다음 패스 Warping Index(타깃 값)가 현재 패스의 피처로 연결되는 구조가 다수 실험(예: scripts/012_...py, scripts/017_...py)에서 포착되었다. 이로 인해 모델이 한 패스 앞선 미래 정보를 미리 참고하는 누수가 발생하였다.

Pattern C (Transductive Leak): 데이터 분할 전에 전체 데이터셋의 통계치가 산출·적용되어 테스트 세트 분포 정보가 훈련 세트에 유입되는 문제가 확인되었다. 예를 들면 014_experiment.py에서는 Train/Test 구분 이전에 StandardScaler().fit_transform(X)가 실행되고 있었고, RM 특징량 생성 시에도 초기에는 전 구간 평균값이 사용되었다. 이러한 전역 통계 사용으로 훈련 단계에 테스트 데이터의 특성이 반영되어 결과적으로 검증 점수를 부풀리는 효과가 발생했다.

Pattern D (Target-Aware Filtering): 이상치 제거 등 데이터 필터링 과정에서도 누수가 발견되었다. 014_experiment.py에서는 IsolationForest 기반의 아웃라이어 제거가 train_test_split 이전 전체 데이터에 대해 수행되었는데, 이 과정에서 테스트 데이터의 존재가 모델이 학습할 훈련 샘플 선택에 영향을 미쳤다. 즉, 테스트 구간의 특이값 분포에 따라 어떤 훈련 데이터가 제외될지가 결정되어 버리는 누수 경로가 있었다.

Pattern E (Cross-Reference Leak): Entry→Exit 교차 예측(E2X, X2E) 모델들의 데이터 병합 단계도 면밀히 점검되었다. 감사 결과 특정 Phase 이후(예: scripts/084_test.py) 동일 패스의 Entry-Exit 행이 잘못 맞물리면서 미래 패스 정보가 혼용되는 버그가 보고되었으나, Phase 3 시점에서는 주된 원인으로 확인된 바는 없다. 다만 연구팀은 잠재적 위험 요소로 인지하고 코드상 인덱스 정합성 검증 로직을 강화하였다.

Pattern F (Importance Weighting Leak): 이전 실험(scripts/012_...py 등)에서 도입되었던 도메인 중요도 가중치(IW: Importance Weighting) 기법이 누수를 유발하는 것으로 밝혀졌다. 해당 기능은 Train과 Test 데이터를 합쳐 분류기를 학습함으로써 표본 가중치를 계산하는 방식인데, 본질적으로 테스트 세트의 피처 정보를 훈련 과정에 활용하므로 데이터 누수로 판정되었다. Phase 3에서는 이러한 Transductive한 기법 일체를 사용하지 않도록 하여 모델 검증의 순수성을 확보하였다.

결함 수정 및 코드 리팩토링: 위와 같은 누수 요인을 제거하기 위해 015~017번 실험에 걸쳐 단계적 수정이 가해졌다. 특히 017_test.py에서는 Lag 기법을 도입하여 미래 패스의 정보를 한 패스 뒤로 지연시켰다. Lag 적용 여부에 따른 성능 변화를 살펴보면, Lag 미적용 시 기존 모델의 Test R²가 약 0.9060이었던 반면 Lag 적용(L1) 후에는 0.6664로 급감하였다. 이를 통해 sequence 누수(Pattern B)의 영향력이 정량적으로 입증되었으며, 연구팀은 이후 실험의 기본 설정에 Lag을 포함시키기로 결정하였다. 아울러 동일 판 내 연속 패스 간 유출을 막기 위해 쌍(Pair) 특성 인코딩이나 동일 패스 출력 활용 특성(예: 현재 패스 변형값인 CUR_WARP 관련 항목) 등을 비활성화하였다. 한편 전역 통계 사용 문제(Pattern C)를 해결하고자 018_experiment.py부터는 훈련 세트 기준 통계 산출 모드(USE_RM_TRAINONLY)를 도입하여, 특성 스케일링이나 롤링 평균 계산 시 훈련 데이터에 한정된 값만 사용하도록 변경하였다. 이상치 제거 역시 필요할 경우 훈련 세트를 기준으로 별도 수행하거나, Phase 3 이후에는 아예 해당 단계를 생략하여 모델이 검증 단계 이전에 테스트 정보를 간접적으로라도 접하지 않도록 조치하였다.

이러한 기능 수정과 더불어, 018~025번 실험에서는 전반적인 코드 구조 리팩토링이 병행되었다. 중복되고 비대한 단일 스크립트를 개선하기 위해 데이터 로더, 모델 학습 루틴, 공통 유틸리티 함수를 별도 모듈로 분리하였다. 그 결과 025_test_no_op.py부터는 본문 길이가 이전 파일 대비 1/3 수준으로 감소하여(약 12KB → 4KB), 각 실험 스크립트는 argparse로 실험 파라미터만 입력받아 공용 모듈의 함수를 호출하는 경량 래퍼 형태가 되었다. 예를 들어 024_test_no_op.py 헤더에는 개별 모델 정의 코드가 포함되어 있었으나, 025_test_no_op.py에서는 from model import train_model 식으로 외부 모듈을 참조하는 것으로 대체되었다. 이처럼 구조적 리팩토링을 통해 코드 가독성과 관리 효율이 향상되었으며, Phase 4 이후 실험에서는 동일 코드 기반에서 하이퍼파라미터만 변경하여 빠르게 반복실험을 수행할 수 있는 기반이 마련되었다.

3. 실험 결과 및 시사점
Phase 3의 조치 결과, 모델 성능 지표가 대폭 현실화되었다. 데이터 누수 차단 전에는 검증 데이터 R²가 0.9 이상으로 보고되었으나, 주요 누수원을 제거한 이후 실시한 동일 조건 실험에서는 해당 수치가 약 0.66 수준으로 하락하였다. 이는 기존 고성능이 실제 예측력이 아닌 누수에 기인한 허수였음을 강력히 시사한다. 나아가 Permutation 기반 감사에서 permuted R²가 초기의 0.92에서 0에 수렴하도록 개선되었고, Train/Test 간 정보 격리가 달성되면서 엄격한 롤-포워드 평가에서도 정상 범주의 R²가 확인되었다. 결국 Phase 3을 통해 모델의 신뢰할 수 있는 기준선 성능이 재설정되었으며, 이를 바탕으로 이후 단계에서는 누수가 제거된 깨끗한 데이터 환경에서 알고리즘 개선을 모색할 수 있게 되었다. 또한 본 Phase에서 수행된 모듈화 및 검증 강화 조치는 추후 딥러닝 아키텍처 도입 시에도 코드 안정성과 재현성을 담보하는 밑거름이 될 것으로 평가된다. 연구팀은 본 감사 결과를 계기로 데이터 전처리 및 피처 엔지니어링 단계에서의 검증 규칙을 한층 엄격히 적용하고, 성능 지표 해석 시에는 항상 잠재적 누수 가능성을 염두에 두는 연구 문화를 정착시켰다.
